# 규칙 점검

에이전트에게 지우는 규칙과 검사를 늘 의심하고, 꼭 필요한지 확인하는 절차다 (2026-11-27 사용자 결정).
실험 기능(단체방 · 토론 · 흐름처럼 해 보는 중인 것)도 같은 목록 · 같은 차례로 다룬다: 해 보고 좋으면 남기고, 별로면 이유를 남기고 되돌린다 (같은 날 사용자 결정).
앱의 소개 › 연구(「연구 중인 기능과 실험」 · 「에이전트 규칙」)가 이 목록을 표로 보이고, 결정을 기다리는 줄은 알림 「답할 것」에 뜬다.
모델이 나아지면 예전에 필요했던 규칙이 짐이 된다. 규칙은 쌓이기만 하기 쉬우므로, 규칙마다 효과를 잴 방법과 다시 볼 날을 같이 둔다.

## 목록

`registry.json`에 규칙 · 실험 하나가 한 항목이다. 모양은 `packages/core/src/contract/rules.ts`가 검사하고(`pnpm test`의 `apps/server/src/ruleRegistry.test.ts`), 계산은 `apps/server/src/ruleRegistry.ts` 하나를 화면과 `pnpm agent:rules`가 같이 쓴다.

| 칸 | 뜻 |
| --- | --- |
| `id` · `rule` · `where` | 이름, 한 줄 내용, 어디에 적혀 있거나 무엇이 검사하는지 |
| `kind` | `safety`(비밀값 · 고위험 합치기 · 저장 공간 같은 사고 막기) · `quality`(코드 · 화면 품질) · `process`(일하는 차례) · `format`(글의 모양) · `experiment`(실험 기능) |
| `audience` | 규칙의 대상: `uses`(앱을 쓰는 에이전트, 연구 저장소에서 일함) · `fixes`(앱을 고치는 에이전트) · `both`. 규칙은 반드시, 실험은 적지 않음 |
| `enforce` | 규칙을 지키게 하는 방식: `prompt`(글: 지시문으로 주고 지키기를 기대함) · `code`(앱 · 검사가 막음) · `both`. 규칙은 반드시 |
| `toCode` | 글로만 지키는 규칙을 코드로 옮길 길 (있으면) |
| `gauge` | 잴 것을 말로 (git으로 셀 수 없는 것). 실험은 반드시 |
| `since` · `why` | 언제 무엇 때문에 생겼는지 |
| `measure` | 잴 것. `attest`: 이 규칙 때문에 커밋 메시지에 쓰는 줄(정규식), `touch`: 이 규칙이 지키는 파일. 없으면 `null` |
| `review` | 다시 볼 날. 새 규칙은 30일 뒤, 효과를 확인한 규칙은 60일 뒤 |
| `verdict` · `note` | 지금 판단(`keep` 유지 · `relaxed` 완화 · `removed` 없앰 · `ask` 결정 필요 · `watch` 지켜봄 · `hold` 보류 · `reverted` 되돌림)과 근거. 보류 · 되돌림 · 없앰은 알리지 않고, 되돌림 · 없앰도 줄은 지우지 않는다(화면에서 접힘) |

결정을 기다리는 줄(`ask`)에 사용자가 화면에서 누른 답(「진행」 · 「그대로 두기」)은 개인 저장소 `feedback/rules.yaml`에 남는다. `pnpm agent:rules`가 답을 보이면(맥에서는 개인 저장소 사본을 저절로 읽고, 다른 곳은 `--answers <피드백 폴더>`) 그대로 반영하는 PR을 올리고 `verdict`를 고친다.

## 차례

1. **새 규칙을 더할 때**: 목록에 한 줄을 더한다. 이유와 잴 것을 못 적으면 규칙이 아니라 이번 한 번의 지시다. 기계가 판정할 수 있으면 글로 적기보다 검사나 앱 기능으로 만든다(에이전트가 외울 것을 줄인다).
2. **다시 볼 때**: `pnpm agent:rules`(기본 30일)가 다시 볼 날이 지난 규칙과 커밋의 25% 넘게 의례 줄을 쓰게 하는 규칙을 알린다. 매달 한 번, 그리고 에이전트의 모델이 바뀐 주에 돌린다.
3. **판단**: 알린 규칙마다 막은 것(CI 실패 가운데 진짜 문제를 잡은 것, 사고)과 치른 것(의례 줄, 숫자만 고친 커밋, 기다린 시간)을 본다.
   - 막은 것이 있다 → `keep`, `review`를 60일 뒤로.
   - 막은 것이 없고 치른 것이 있다 → 풀자고 사용자에게 제안하고, 허락받으면 `relaxed` · `removed`.
   - 자료가 모자라다 → `watch`, 무엇을 더 잴지 `measure`에 적는다.
   - 실험: 효과가 있다 → `keep`. 사용자가 멈췄다 → `hold`. 효과가 없다 → 되돌리자고 제안하고(`ask`), 허락받으면 기능을 되돌리는 PR과 함께 `reverted`와 이유.
4. **안전 규칙**(`safety`)은 효과가 보이지 않아도 사용자 허락 없이 풀지 않는다. 사고는 드물게 일어나서 몇 주의 이력으로는 효과를 잴 수 없다.
5. **푸는 PR**에는 전후 수(의례 줄 비율, 실패 수)를 적고, 고위험 영역(`scripts/ci/` 등)이면 사용자가 합친다.

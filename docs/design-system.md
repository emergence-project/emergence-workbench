# 연구 작업대 디자인 시스템

화면을 만들거나 고칠 때 따르는 기준이다. 정본의 순서는 **이 문서 → `apps/web/src/tokens.css` → main에서 찍은 `pnpm shots` 그림**이다. CLAUDE.md "화면 기준"은 이 문서의 요약이다.

처음 세운 날: 2026-10-03 (사용자 요청 "디자인 시스템 도입을 위해 상용앱의 디자인 원칙으로 점검"). 점검 기록과 전후 그림: [작업대 디자인 점검](https://claude.ai/artifact/X4JYtjAhs5NyQEW9rqGePV).

## 1. 원칙

| 원칙 | 출처 | 이 앱에서 뜻하는 것 |
| --- | --- | --- |
| 위계 | Apple HIG (Hierarchy) | 화면마다 가장 중요한 것 하나가 먼저 보인다. 큰 제목은 한 번. 색은 꼭 알아야 할 상태에만 |
| 일관성 | Apple HIG (Consistency) | 같은 일은 같은 모양. 텍스트 버튼, 선택 표시, 태그, 헤더가 어느 화면에서나 같다 |
| 구조는 드러나지 않게 | Linear ("structure should be felt, not seen") | 테두리와 상자를 줄이고 간격과 정렬로 묶는다. 상자는 따로 떼어 볼 물건에만 |
| 기초 토큰 먼저 | Atlassian (Foundational), GitHub Primer foundations | 색·글자·간격·모서리는 정해진 단계에서만 고른다. 단계가 모자라면 화면이 아니라 토큰을 먼저 고친다 |
| 한 가족 | Atlassian (Harmonious) | 카드·칩·버튼은 어느 화면에 있든 같은 부품이다. 비슷한 것을 새로 만들지 않고 있는 부품을 쓴다 |
| 조금씩 다듬기 | Linear ("evolution over revolution") | 한 번에 갈아엎지 않는다. 작은 PR로 고치고 전후 그림을 본다 |

## 2. 값 (토큰)

모든 값은 `tokens.css`에 있다. 새 값이 필요하면 거기에 더하고(색은 라이트·다크 둘 다), 이 표도 고친다.

### 색

| 역할 | 토큰 | 쓰는 곳 |
| --- | --- | --- |
| 바탕 | `--bg`, `--bg-side`(사이드바), `--bg-sunken`(움푹한 칸·칩 바탕), `--bg-hover`(가리킴·선택) | |
| 선 | `--line`(기본), `--line-strong`(버튼 테두리·점선) | |
| 글자 | `--text`(본문·이름), `--text-2`(설명·텍스트 버튼), `--text-3`(보조 정보·빈 상태) | 글자는 이 셋 중에서 |
| 강조 | `--primary` / `--on-primary` | **주 버튼과 선택 표시에만** (설정의 강조 색이 여기만 바꾼다). 고를 수 있는 색의 라이트 값은 `--accent-indigo` · `--accent-plum`(설정 화면 견본은 두 테마에서 이 값), 다크 값은 `tokens.css`의 `data-accent` 규칙에 |
| 상태 | `--s-progress` 파랑 진행 · `--s-blocked` 주황 멈춤 · `--s-stopped` 짙은 회색 폐기(속 빈 고리) · `--s-solved` 청록 해결 (노트·연구노트 카드·진술 같은 이름, 10/4) | 상태 색 점(`StatusDot`)에만. 진술은 옅은 점 증명 작업 없음, — 공리·정의 |
| 위험 | `--danger`, `--danger-bg` | 지우기·오류에만 (10/6 결정: 홈의 "확인 필요" 빨간 점도 주황으로 바꾼다) |
| 사용자 차례 | `--s-blocked` 주황 (배지 `.rail-count`, 새 버전 점, 피드백 "확인 필요", 홈 "확인 필요") | 사용자가 보거나 정할 것은 어디서나 주황 하나의 모양(수 · 점). 멈춤도 "기다리는 중"이라 같은 주황을 쓴다. 에이전트 차례(질문 "에이전트 대기", 피드백 처리 "대기")와 처리 상태 태그는 무채색 (10/6 결정, D5) |
| 표시 | `--focus`/`--focus-line`(지금 가리키는 곳), `--hl-bg`(PDF 하이라이트), `--mark-bg`(글 속 하이라이트), `--select-bg`(PDF 글자 선택), `--paint-yellow`·`-green`·`-blue`·`-pink`(노트 · 편집기 · PDF 하이라이트 네 색, 이름 없이 색 점으로 고른다) | |
| 기록 메뉴 | `--record-menu-ink`(검은 메뉴 · 흰 메뉴의 글자), `--paper`(흰 메뉴 · 검은 메뉴의 글자) | 두 테마에서 고른 글 메뉴는 검은 메뉴, 하이라이트 메뉴는 흰 메뉴 |
| 프로젝트 | `--proj-1`…`--proj-5` | 홈 달력의 프로젝트 구분 (프로젝트 아바타 색은 데이터) |
| 카드 | `--card-bg`(주제·노트 카드 바탕), `--tc-violet` #ede7fb · `--tc-blue` #e3eefb · `--tc-teal` #e0f2ef · `--tc-orange` #fbefe0 · `--tc-gray` #efefee (다크는 같은 색조의 어두운 값, 회색은 그림 칸 #4a4a47), `--tc-mix`(기본 바탕 = 프로젝트 색을 이만큼 섞은 옅은 색, 라이트 14% · 다크 24%) | 주제 카드 위쪽 미리보기의 바탕색. 정해 둔 다섯 색과 기본만 고른다(색마다 라이트·다크 값을 맞춰 둬야 해서, 10/5) |
| 기타 | `--on-color`(색 바탕 위 흰 글자), `--scrim`(대화상자 뒤), `--paper`(그림 바탕), `--banner-*`(예제 모드 배너), `--code-*` | |

**다크** (10/5 "밝은 다크"): 바탕 `--bg` #2b2b2a · 카드 `--card-bg` #363634 · 움푹한 칸 `--bg-sunken` #3b3b38(카드 위 칩이 보이게, 10/6 점검) · 그림 칸 `--tc-gray` #4a4a47, 글자 #f0f0ee · #b4b4af · #9a9a95 (보조 글자도 카드 위에서 4.3:1 넘게). 다크 값은 `tokens.css`의 `prefers-color-scheme`과 `data-theme="dark"` 두 곳에 같은 내용으로 있으니 함께 고친다. `pnpm shots`의 `dark-*` 그림으로 확인하고, `pnpm shots --theme dark`면 모든 화면을 다크로 찍는다.

`--link`는 입력란 초점 테두리에만 쓰고 무채색이다 (10/4). 파랑은 "진행" 상태에만 쓰므로 글자 링크·버튼·초점에 쓰지 않는다.

상태 색 넷은 색을 잘 못 가리는 눈(적록 색약)으로 봐도 서로 갈리게 골랐다 (10/4 점검: 주황–청록, 파랑–주황은 어느 눈에도 멀다). 짙은 회색과 청록은 적록 색약에서 가까워지므로 폐기는 속 빈 고리 모양으로도 구별한다. 강조 색 "청록"은 해결 색과 겹쳐 뺐다.

### 글자

| 크기 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--fs-2xs` | 10.5px | 칩 글자, 단축키, 아주 작은 수 |
| `--fs-xs` | 11.5px | 보조 정보, 날짜, 개수 |
| `--fs-sm` | 12.5px | 버튼, 헤더, 표 |
| `--fs-md` | 13.5px | 본문 기본 |
| `--fs-lg` | 16px | 사이드바 블록 이름, 소제목 |
| `--fs-xl` | 21px | 화면 큰 제목 (`.h-title`) |

굵기는 네 단계: `--fw-normal` 400 본문 · `--fw-medium` 500 이름 · `--fw-strong` 600 선택·칩·주 버튼 · `--fw-title` 650 제목.

크기는 설정의 글자 크기(`--ui-scale`)를 따라 커지고 작아진다. 글 본문(마크다운) 안의 em 비율은 예외로 둔다.

### 간격과 모서리

- 간격: `--sp-1` 4 · `--sp-2` 8 · `--sp-3` 12 · `--sp-4` 16 · `--sp-5` 24 · `--sp-6` 32 (설정의 촘촘함 `--density`를 따른다). 이 여섯 값은 반드시 토큰으로 쓴다. 2·3·6·10px 같은 작은 맞춤 값은 단계 사이를 메우는 데만 쓴다.
- 모서리: `--r-xs` 4 작은 칩 · `--r-sm` 6 버튼·입력란 · `--r-md` 10 목록 칸·작은 카드 · `--r-lg` 14 큰 카드·사이드바 블록 · `--r-pill` 둥근 태그. 3px 이하 작은 표시와 원(50%)은 그대로 쓴다.
- 입력란 높이: `--input-h` 28px(화면 안 입력란 · 찾기 칸), `--input-h-lg` 34px(고치기 창). 같은 줄 버튼도 같은 높이 (10/6 D1).
- 프로젝트 고치기 창: `--project-dialog-width` 760px(전체), `--project-preview-width` 280px(입력·미리보기 칸의 최소 폭). 좁으면 한 열로 놓는다.
- 분류 고르기 메뉴(라이트·다크 공용): `--subject-menu-width` 320px, 창이 좁으면 화면 안으로 줄인다.
- 카드 그림 고르기(라이트·다크 공용): `--card-picker-width` 520px(창), `--card-picker-column` 136px(격자 최소 폭), `--card-picker-preview-height` 96px(그림 높이), `--card-picker-thumb-width` 36px(선택값 그림 폭), `--card-picker-border` 1px(테두리), `--z-card-picker` 51(고치기 창 위).
- 논문 표 폭(라이트·다크 공용): `--pl-col-title` 200px(제목 최소 폭), `--pl-col-authors` 170px, `--pl-col-year` 64px, `--pl-col-venue` 190px, `--pl-col-arxiv` 100px, `--pl-col-projects` 150px, `--pl-col-pdf` 80px, `--pl-col-comments` 100px, `--pl-col-opened` 100px, `--pl-col-kind` 64px, `--pl-col-key` 150px. 사용자가 끌어 정한 폭은 저장한 값을 쓴다.
- 지식 표 폭(라이트·다크 공용): 제목 최소 폭은 `--pl-col-title` 200px를 공유하고 남은 폭을 채운다. `--kl-col-subject` 144px, `--kl-col-projects` 128px, `--kl-col-num` 56px(출처·링크), `--kl-col-issues` 112px, `--kl-col-date` 64px(MM-DD), `--kl-col-aliases` 160px, `--kl-col-checked` 120px. 기본 일곱 열의 최소 폭 합계는 760px.
- 주제·노트 카드(라이트·다크 공용): `--kc-card-width` 184px, `--kc-card-gap` 14px. 촘촘함과 무관하게 고정하며 일반 카드·점선 만들기 카드·격자가 함께 쓴다.
- 주제 화면 문서 최대 폭: `4 × --kc-card-width + 3 × --kc-card-gap + 2 × --sp-6`(카드 네 장 + 카드 사이 간격 + 본문 좌우 여백, 작업 패널 없음). 촘촘함 1에서는 842px, 0.72에서는 824.08px이며 카드 영역은 778px다. 가용 폭이 작으면 문서도 줄어들고 카드가 다음 줄로 넘어간다.
- 프로젝트 첫 화면 작업 패널: `--landing-work-min-width` 260px(최소), `--landing-work-width` 300px(최대). 문서 최대 폭은 `4 × --kc-card-width + 3 × --kc-card-gap + --sp-5 + --landing-work-width + 2 × --sp-6`(카드 네 장 + 카드 사이 간격 + 두 패널 사이 간격 + 작업 패널 + 본문 좌우 여백). 촘촘함 0.72에서는 1141.36px, 1에서는 1166px이며 창의 가용 폭이 작으면 줄어든다. 카드 네 장의 폭 778px를 우선 확보하며 작업 패널이 먼저 300px에서 260px까지 줄어든다. 그 최소 폭으로도 모자라면 카드 칸이 남는 폭을 쓰고 카드가 다음 줄로 넘어간다.
- 라이브러리 첫 화면(라이트·다크 공용): `--lib-page-width` 1080px(좌우 여백 포함 최대 폭), `--lib-card-min` 180px(작은 카드 최소 폭), `--lib-cover-h` 112px(표지·미리보기 높이), `--lib-card-min-h` 160px(카드·점선 더하기 카드 최소 높이). 본문 여백은 위 `--sp-5` · 좌우 `--sp-6` · 아래 `--sp-6 + --sp-2`, 가운데 정렬.
- 논문 카드 폭(라이트·다크 공용): `--pl-card-width` 184px. 점선 더하기 카드도 같은 폭·높이이며 줄이 바뀌어도 높이를 맞춘다.
- 그림자: `--shadow-sm`(눌린 세그먼트), `--shadow`(떠 있는 카드·메뉴). 가만히 있는 카드에는 그림자를 주지 않는다.

## 3. 부품

새 화면은 아래 부품을 쓴다. 맞는 것이 없으면 부품을 하나 더하고 이 표에 적는다.

| 부품 | 클래스 | 언제 |
| --- | --- | --- |
| 주 버튼 | `.btn.primary` | 화면에서 가장 중요한 행동 하나 (컴파일, 저장, 만들기) |
| 테두리 버튼 | `.btn` | 그 밖의 행동 (복사, 열기, 되돌리기) |
| 텍스트 버튼 | `.a` | 글 사이에 놓이는 가벼운 행동·이동 ("작업", 원고 이름). 무채색, 가리키면 밑줄 |
| 아이콘 버튼 | `.icon-btn` | 상단바·툴바. `title`에 하는 일을 적는다 |
| 기호 버튼 | `.btn.btn-icon` (주 버튼이면 `.btn.primary.btn-icon`) | 툴바의 자주 쓰는 행동을 기호만으로 (원고 컴파일 ▶, 내보내기 ⤓). `title`·`aria-label`에 하는 일을 적는다. 기호는 가운데에 놓는다(정사각형 버튼도). ▶ 그림은 눈으로 보아 가운데가 되게 조금 오른쪽으로 치우쳐 그려 두었다 |
| 세그먼트 | `.segmented` | 보기 전환 · 필터 (목록/지도, 테마) |
| 선택 표시 | `.on` → `--bg-hover` 바탕 | 지금 고른 것. 굵은 테두리·레일을 따로 만들지 않는다. 예외 둘(10/6 D2): 늘 흰 바탕인 그림 미리보기 카드(`.fg-card`)와 색 아바타인 레일 프로젝트(`.rail-proj`)는 바탕이 안 보이므로 `--text` 테두리 · 고리로 고른다 |
| 태그 | `.kn-st`, `.tag`, `.kind-chip` | 한국어로. 상태가 아니면 무채색. 진술 종류는 색이 아니라 진하기(정리 > 명제·보조정리·따름정리 > 공리·정의) |
| 카드·상자 | `.card`, `.note-card`, `.pcard`, `.rows`, `.now`, 표 상자 | 화면에 놓인 상자는 모두 `--r-lg` 모서리, `--line` 테두리. 눌러서 여는 카드는 가리키면 `--line-strong` + `--shadow`. 상자 안의 작은 칸은 `--r-md` 이하 |
| 툴바 | `.pane-head` | 도구(버튼·필터)와 개수·날짜 같은 짧은 정보만 둔다. 화면 이름은 상단바가 보여 주므로 다시 쓰지 않는다 |
| 개념노트 툴바 | `NoteToolbar` (`data-ui="머리줄"`) | 노트 툴바와 같은 줄(10/10 노트 화면 틀). 왼쪽은 무채색 기호와 "확인함" / "확인 전", 잠긴 노트는 "잠김" 태그. 오른쪽은 저장 상태 · 연필 · ⋯(파일 다시 읽기). 고치는 동안 저절로 저장하고 "편집 완료"(Esc · ⌘S)로 마친다. 잠긴 노트의 연필은 고치는 동안만 잠금을 풀고 편집 완료 때 다시 잠근다. 잠그기 · 풀기는 문서 정보의 체크. 오른쪽 정보 칸과 본문 열은 고치는 동안에도 같은 자리를 쓴다(D8) |

### 표시 기호 (누르는 것이 아님)

- **상태는 글자 기호가 아니라 색 점과 두 글자 이름이다** (10/4 사용자 결정 "기호 말고 색으로", "짧은 이름으로"): 진행 · 멈춤(기다리는 중, 곧 다시) · 폐기(그만둠, 지우지 않음) · 해결. 노트·연구노트 카드·진술이 같은 이름을 쓴다. 자료 값(`in-progress`·`blocked`·`stopped`·`solved`)은 그대로다.
- 점은 `StatusDot`(`apps/web/src/StatusDot.tsx`, `.g`)만 쓴다. 자리가 있으면 이름을 함께(`label`), 사이드바처럼 좁은 곳은 점만 두고 가리키면 이름이 뜬다. 진술은 `ProofMark`: 증명 작업의 색 점, 증명 작업 없음은 옅은 점, 공리·정의는 —.
- ● ⏸ ■ ◆를 화면 코드에 글자로 쓰지 않는다 (`check-design.mjs`가 잡는다). ▶ 컴파일 옆에서 재생기 단추로 읽히고, ◆는 개념노트 그림과 겹친다.
- **상태 점은 늘 상태 색, 행동 기호는 늘 무채색.** 상태 점을 누르는 곳은 연구노트 카드의 "상태 바꾸기" 하나이고, 누르면 넷 중에서 고르는 목록이 열린다.
- 결과 줄: 성공 ✓(무채색), 오류 ! (위험 색). 하는 중은 "… 중" 글자로. 컴파일 결과는 "✓ 컴파일 완료" · "! 오류 N", 노트 툴바의 "이번 컴파일 실패"도 위험 색이다 (10/8).
- `!`는 오류 한 가지 뜻이다. 할 일 마감은 깃발 ⚑(사용자 차례 주황)로 적는다: 홈 달력 · 작업 탭 달력 (10/8, 예전에는 !).
- ✓는 "끝남·확인됨" 한 가지 뜻이다 (컴파일 성공, 확인함, 승인함, 끝낸 할 일). 연구 상태의 해결은 ✓가 아니라 청록 점이다.
- 개념노트의 사용자 확인은 "확인함" / "확인 전" 한 쌍으로 표시한다(D8). 본문 완성도를 거르는 "미완성"은 이름과 조건을 유지한다. 확인함은 무채색 ✓, 지도에서는 `--text` 실선 테두리이며 확인 전은 `--line-strong` 테두리다. "프로젝트가 씀"은 `--text-2`의 프로젝트 기호로 표시한다.
- ✎ 글자는 "고친 기록"(달력의 작업노트 고침)에만. 고치기 버튼은 연필 그림.
- ★ 즐겨찾기 (☆ 아직 아님). 카드·사람 모두 같은 이름이다 ("중요 표시"라고 쓰지 않는다). 색을 주지 않는다.
- ⇄ 상태 바꿈 (달력·일지의 기록 표시). →는 열기·이동에만 쓴다.
- 맡긴 일의 상태 점은 노트 상태 색을 그대로 쓴다(진행 파랑 · 판단 대기와 종결 조건 승인 대기와 멈춤 주황 · 해결 청록 · 폐기 회색 고리). 판단 대기 점은 색만 멈춤과 같고, 이름(툴팁)은 "판단 대기"다.
- 끝난 상태의 이름: 연구 일(노트 · 맡긴 일)은 "해결", 프로젝트와 피드백은 "완료"다. 맡긴 일 목록의 끝난 묶음은 "해결 · 폐기"로 적는다. "끝남·종료"는 상태 이름으로 쓰지 않는다 (10/8 사용자).
- 물리·수학 "검토 대기"는 사용자 차례라 주황 알약 수로 적는다(프로젝트 첫 화면 작업 패널, 작업 탭) (10/8 사용자).
- 사용자 차례의 수는 어디서나 레일 배지(`.rail-count`)와 같은 주황 알약이다: 레일, 피드백 필터, 프로젝트 첫 화면, 라이브러리 점검(`.kh-count.turn`), 작업 탭 판단(`.tk-cnt.turn`) (10/8).
- 홈의 상태 기호: 주황 점 확인 필요(사용자 차례), 돌아가는 화살표(`Icon.sync`, 글자 ↻ 아님) 업데이트 필요, 둘 다면 화살표 오른쪽 위 주황 점. 프로젝트 진행 상태(진행 · 멈춤 · 완료)는 노트 상태와 같은 색 점(파랑 · 주황 · 청록)에 이름.

### 자리

- 항목 하나에 대한 행동(고치기·지우기)은 그 항목 오른쪽 위의 아이콘 버튼 `.icon-btn`. 글 아래 텍스트 버튼으로 두지 않는다. 본문의 넓은 목록에서는 그 아이콘들을 `.hover-actions`로 묶어 항목을 가리키거나 키보드로 골랐을 때만 보인다(터치 화면에서는 늘 보인다). 오른쪽 사이드바 카드 · 좁은 칸에서는 옅은 `--text-3`으로 늘 보인다 (10/6 결정, 10:59 "제거 기능이 없음").
- 화면 전체에 대한 행동은 툴바(`.pane-head`) 오른쪽. 주 버튼은 그중 하나만.
- 여닫는 버튼은 그것이 여닫는 칸 쪽에 둔다.
- 같은 일은 담당 화면 한 곳에서만 한다. 다른 화면의 버튼은 그 화면으로 가는 길이다.

### 확인

- 되돌릴 수 없는 지우기만 확인을 묻는다. 물음에는 무엇이 사라지고 무엇이 남는지를 적는다 ("카드를 지울까요? 원고의 장은 그대로 남습니다").
- ⌘Z나 휴지통 · 보관함으로 되돌릴 수 있는 지우기(하이라이트, 15일 보관 뒤 지우는 노트)는 묻지 않고 바로 지운 뒤 되돌리는 길을 알린다("지웠습니다 · 되돌리기") (10/6 결정).
- 노트 ⋯의 지우기는 원문 파일 하나를 영구히 지우므로 확인을 묻는다. 기록 파일(`workbench/comments/block-<id>.md`)·다른 문서의 링크·기존 PDF는 남고, 남은 링크로 원문을 열 수 없다고 알린다. 연구·계산 노트의 15일 휴지통과 구분한다(기록 PR 5).
- 노트 지우기 알림(`.toast`)의 "되돌리기"는 텍스트 버튼 `.a.toast-action`으로 둔다. 행동이 있는 알림은 8초 동안 보이고, 버튼을 누르면 알림을 닫고 노트를 되살린 뒤 "되살렸습니다"를 알린다.
- 고친 내용을 버리게 되는 닫기는 "고친 내용을 버릴까요?"로 묻는다.
- 빼기·닫기·순서 바꾸기는 묻지 않는다.
- 이름·제목 같은 짧은 글을 받을 때는 `askText()`(`askText.tsx`, 앱 모양의 작은 창)를 쓴다. 브라우저 기본 입력창 `prompt()`는 쓰지 않는다.
- 확인은 `askConfirm({ title: 물음, hint: 무엇이 남는지, ok: '지우기' })`(같은 파일)로 묻는다. 브라우저 `confirm()`은 쓰지 않는다: 화면 창이라 에이전트도 이름으로 찾아 누를 수 있다.

### 기호만 쓰는 버튼

- `title`과 `aria-label`에 하는 일을 한국어 동사로 적는다 ("고치기 — 시작일"). 영어(edit)를 쓰지 않는다.
- 이름이 바로 보여야 하는 기호 버튼(승인·수정·접기)은 `title` 대신 `data-tip="이름"`을 단다. 가리키면 버튼 아래에 툴팁이 곧바로 뜬다(`.icon-btn[data-tip]`, base.css). 긴 설명은 `aria-label`에.
- 새 기호가 필요하면 `icons.tsx`에 더하고 위 표에 적는다. 같은 기호를 두 뜻으로 쓰지 않는다.
- 화면 태그 기호(탭, 사이드바 노트 줄, 노트 목록, 파일 줄)도 `icons.tsx`의 선 그림을 쓴다: 연구노트 `block`, 개념노트 `concept`(마름모), 문헌노트 `paper`(펼친 책), 논문 라이브러리 `papers`(겹친 종이), 그림 라이브러리 `figures`(원과 세모), 라이브러리 목록 `list`(점과 줄 셋), 지도 `tree`, 진술 `statement`, PDF·파일 `pdf`, 카드 `card`. 글자 기호(§ ◇ ▤ ⎙)를 섞지 않는다.

## 5. 글

- 짧고 분명한 말. 디자인 요소의 이름은 아래 용어표의 이름 하나만 쓴다. 고유어로 새 이름을 짓지 않고, 짧은 한자어나 널리 쓰는 외래어(툴바, 필터, 태그)를 쓴다. 문서에는 영어 이름을 함께 적는다 (10/7 사용자 결정, 예: "거르기" → "필터").
- 버튼은 하는 일을 동사로 ("기본값으로 되돌리기", "검토 완료로 표시").
- 위치는 상단바가 알려 준다. 화면 안에서 같은 이름을 두 번 크게 쓰지 않는다.
- 빈 상태는 무엇이 생길지와 어떻게 더하는지를 한 줄로.
- 화면 글은 영어와 한국어 둘 다 쓴다 (10/8 사용자 결정, `apps/web/src/i18n.ts`). 그 자리에 `t('한국어', 'English')`로 적고, 영어는 아래 용어표의 English 이름을 쓴다. 파일·설정에 저장되는 값(기록 종류, 피드백 상태 등)은 한국어 그대로 두고 `shown()`으로 보여 줄 이름만 바꾼다. 서버 메시지는 `apps/server/src/i18n.ts`의 `t`, core는 `tr`. `data-ui`는 두 언어 모두 한국어다. 영어 화면은 `pnpm shots --lang en`(영어 예제)으로 보고, 화면에 남은 한국어를 그 출력이 알려 준다.

## 6. 배치와 쓰는 법 (10/6, 피드백에서 뽑은 규칙)

10/1–10/6 피드백 · 반려 이유 · 대화 결정에서 같은 취향이 되풀이된 것을 규칙으로 적었다. 괄호는 근거(피드백 날짜 시각, 또는 "대화 10/6"). 근거가 사용자 결정이면 **결정**, 두 번 넘게 지적했으면 **반복**이라 적는다. 점검 체크리스트는 이 절과 1–5절에서 나온다(8절 "화면 점검 체크리스트").

### 자리는 움직이지 않는다

- **고정 영역은 내용 길이와 상관없이 같은 자리다.** 프로젝트 첫 화면의 작업 패널은 본문 오른쪽 맨 위에서 시작하고, 왼쪽 내용만 길어진다. 툴바의 보기 고르기는 가운데에 고정한다. (10/6 11:14, 대화 10/6 — **결정**)
- **사이드바는 창 높이 전체를 차지하고 본문 스크롤과 따로 움직인다.** 긴 화면을 끝까지 내려도 잘리지 않는다. (10/6 11:49)
- **끌 수 있어 보이는 경계는 실제로 끌린다.** 끌리지 않으면 끌기 커서 · 강조를 주지 않는다. (10/6 11:43)
- **문서에 대한 정보는 오른쪽 사이드바, 문서에 대한 행동은 툴바 한 줄.** 상태만 툴바 맨 왼쪽에 둔다. 무언가를 적는 곳도 오른쪽 사이드바 하나다. (10/4 18:09 · 18:10, 10/6 10:57, 기록 10/6 — **결정**)
- **무엇을 관리하는 일은 그 물건의 화면 안에서.** 목록 화면에는 그리로 가는 길 하나만 둔다(4절 "같은 일은 담당 화면 한 곳"을 화면 단위로). (10/4 15:38 · 19:08, 반려 10/4 20:51 — **반복**)

### 툴바는 세 구역

- **왼쪽 = 무엇**(대상 이름 · 상태), **가운데 = 어떻게 보나**(보기 고르기, 가운데 고정), **오른쪽 = 행동**(주 버튼은 맨 오른쪽에 하나). (10/6 11:47, 대화 10/6 — **결정**)
- 노트 툴바, 읽는 중: 왼쪽 ● 상태 · 오른쪽 "저장됨 · n분 전"(작은 회색) · 코멘트 · 연필 · ▶ · ⋯. 고치는 중: 왼쪽 제목 입력란(본문 위 제목이 올라온다) · ● 상태, 가운데 원문 · 원문|미리보기 · 미리보기, 오른쪽 "저장됨 · n분 전" · "편집 완료"(주 버튼). 저장 상태는 늘 오른쪽 행동 무리 바로 왼쪽이다. 저장 중이면 "저장 중…", 충돌 · 실패면 그 자리에 색 글자와 해결 단추. (대화 10/6 — **결정**)
- 항목 헤더의 버튼 묶음은 오른쪽 끝에 붙는다. 없는 버튼의 자리를 비워 두지 않는다. (10/4 20:43) 물건 툴바(주제 · 프로젝트)는 ★만 이름 옆, 연필 · 휴지통은 오른쪽 끝 한 묶음 (10/6 D6).
- 상태 단추는 어느 노트에서나 한 모양: 색 점 + 이름, 누르면 넷 중에서 고르는 메뉴 (10/6 D9).
- 탭 바: 탭이 넘치면 탭이 …로 줄어들고, 지금 탭은 늘 보이게 스크롤하며, 넘친 쪽 끝에 옅은 그림자 (10/6 D10).
- 크기가 다른 글자 · 아이콘 · 기호는 글자 몸통을 기준으로 눈으로 보아 가운데 맞춘다. (10/4 17:56, 10/5 21:56 — **반복**)

### 좁은 폭과 다크

- **모든 화면을 두 크기 × 두 테마로 본다**: 1200×735(맥 기준 창, 양쪽 사이드바를 켜고 두 패널)과 1440×900, 라이트와 다크. (requirements "맥 창의 칸 배치" 10/3, 대화 10/6 — **결정**)
- **한글이 한 글자씩 세로로 줄바꿈되면 안 된다.** 태그 · 시각 · 버튼 말 · 칩 · 상태 이름은 줄지 않고 한 줄(`white-space: nowrap`, `flex: none`). 모자라면 긴 이름(제목 · 부위 이름 · 경로)만 …로 줄이거나, 묶음을 통째로 다음 줄로 내린다. (10/5 10:36, 10/6 10:59 · 11:57 — **반복**)
- **좁아지면 덜 중요한 것부터 숨기고**(가리키면 보이게), 그다음에 줄을 넘긴다. 예: 노트 툴바는 저장 시각을 먼저 숨기고("편집 완료"에 마우스), 더 좁으면 보기 고르기를 제목 뒤로 흘린다. 저장 중 · 충돌은 숨기지 않는다. (대화 10/6 — **결정**)

### 팝업 · 메뉴 · 창

- **팝업 · 메뉴는 사이드바나 스크롤 칸에 잘리거나 가려지지 않는다.** 버튼 아래 왼쪽에 맞춰 열고, 화면 끝에 닿으면 펼치는 방향을 바꾼다. 스크롤 칸이 자를 수 있는 곳은 맨 위 층에 띄운다. (10/6 11:23, 대화 10/6 — **결정**)
- 맨 위 층(`document.body`)에 띄운 창 · 메뉴는 그 화면이 숨으면(다른 탭 · 다른 화면) 같이 숨는다. 쓰던 내용은 지우지 않고 돌아오면 다시 보인다.
- **긴 고르기 목록은 펼쳐 두지 않고 찾는 칸이 먼저**, 비어 있으면 자주 쓰는 것 몇 개. (10/4 14:44 · 18:53 — **반복**)
- 창이 열려 있어도 앱 버튼(피드백 등)은 창을 닫지 않고 쓸 수 있고, 창 안의 부위에도 `data-ui` 이름을 단다. (10/5 10:57)

### 고치기

- **읽기가 기본이다. 입력란은 평소 닫혀 있고 연필을 누를 때만 열린다.** (10/4 17:58 · 18:55 · 18:56 · 19:30 — **반복**) 예외: LaTeX 화면(.tex 노트 · 원고 장 · 진술)은 원문이 곧 읽는 모양이라 원문 편집기가 늘 열려 있다 (10/6 D4).
- 같은 값을 두 화면에서 따로 고치지 않는다. 프로젝트 정보 화면은 읽기 + 제목 옆 연필 하나가 첫 화면과 같은 고치기 창을 연다(시작일 · 카드 그림도 창에) (10/6 D3).
- **값 하나는 그 자리에서**: 노트 제목 밑줄 칸, 오른쪽 사이드바 `.rs-select`. **물건 하나(프로젝트 · 주제 · 사람)의 여러 칸을 함께 고치는 것은 고치기 창 한 모양**(`CardEditDialog`): 머리에 프로젝트 색 막대 · "○○ 고치기" · 위치, 왼쪽에 칸들, 오른쪽에 바꾸는 대로 보이는 실제 크기 카드 미리보기와 같은 폭의 취소(Esc) · 저장(⌘↵). 화면 안에 큰 입력란 양식을 펼치지 않는다. (10/5 22:36, 10/6 11:22, 대화 10/6 — **반복 · 결정**)
- **입력란은 한 모양**: 얇은 `--line` 테두리, 높이 두 단계 — 화면 안 입력란 · 찾기 칸 `--input-h` 28px, 고치기 창 `--input-h-lg` 34px (10/6 D1). 같은 줄의 입력란과 버튼은 높이가 같다. 평소에 굵은 검은 테두리를 두지 않는다(초점일 때만 진하게, 주제 고치기 창과 같게). (10/5 22:22, 10/6 11:22 · 11:30 — **반복**)

### 아이콘과 글자

- **항목 · 카드의 행동은 글자 링크 대신 아이콘**(+ `data-tip` 이름). (10/4 15:52 · 19:06 · 20:43, 10/6 11:09 — **반복**)
- **대상으로 가는 링크를 따로 두지 않는다.** 대상 이름(위치 글자 · 제목) 자체를 누르면 그리로 간다(가리키면 밑줄, `data-tip`에 "그 자리로 가기"). 따로 된 "…로 가기 →" 글자를 두지 않는다. (10/6 11:09, 대화 10/6 — **결정**)
- **할 수 있는 일은 화면에 드러나야 한다.** 숨은 방법(낱말로 찾기, 끌어서 순서, 가리켜야 보이는 아이콘)에는 보이는 단서 한 줄이나 늘 보이는 아이콘을 둔다. (반려 10/5 22:26, 10/6 10:59 · 11:50, 10/5 09:52 — **반복**)
- 기호와 짧은 말은 뜻이 바로 읽혀야 한다. 무엇에 대한 행동인지 태그나 목록 머리에 적는다. (10/4 16:16 · 19:36 — **반복**)
- 칸 이름은 짧게, 내용과 범위를 드러내게("쓰는 개념노트" → "개념노트", "앱 업데이트" → "앱 기본정보"). 화면에 설명 글을 늘어놓지 않는다: 뜻은 이름 · 기호 뜻 표 · 가리키면 보이는 말로. (10/4 18:17 · 19:30 · 19:43, 10/5 21:57 — **반복**)

### 목록 · 카드 · 빈 상태

- **긴 목록은 다 펼치지 않는다**: 찾기 먼저, 접힌 묶음, 한 줄 + "n개 더 보기". 긴 경로 · 분야는 마지막 이름만 보이고 전체는 가리키면. (10/2 22:48, 10/4 14:44 · 19:07 · 반려 19:20 — **반복 · 결정**)
- **카드에는 최소만**: 제목 · 짧은 설명 · 꼭 필요한 것 하나. 표 · 카드의 칸은 한 줄(넘치면 …, 가리키면 전체), 칸 높이를 고정해 줄을 맞춘다. ★ 즐겨찾기가 먼저, 그다음 정한 정렬. (10/4 15:40 · 16:19, 10/5 확정 — **결정**)
- **기록 하나 = 상자 하나.** 상자는 따로 떼어 볼 물건(기록 · 카드)에만 쓰고, 빈 상태 글 · 설명에는 상자를 두지 않는다. (10/4 19:17)
- **빈 상태 글은 상자 없는 `--text-3` 한 줄**이고 어느 화면에서나 같은 모양이다(무엇이 생기고 어떻게 더하나). (10/6 11:30)
- **라이브러리 첫 화면(아무것도 고르지 않았을 때 · 0개일 때)은 빈 칸이 아니라 출발점이다**: 어디에 저장되는지(이 맥 · Git · Google · iCloud), 찾기 · 분류, 최근 것. 설계는 따로 한다(10/6 11:10 질문). (10/6 11:10 · 11:25 · 11:26 — **반복**)
- **설정의 절은 모두 같은 모양**: 제목 · 설명(같은 폭) · 입력 줄(입력란 + 버튼 같은 높이) · 빈 상태. 관련 설정은 한 절 안의 하위 절로 묶는다. (10/4 19:29, 10/6 11:30 — **반복**)
- 사용자가 쓴 글(설명 · 메모 · 피드백)은 어디서나 같은 Markdown으로 그린다. "- " 목록은 •, 하위는 ◦, 그 아래 ▪. (10/6 11:00 · 11:14 — **반복**)

### 화면 검사 명령과 범위

크기·테마·샘플은 환경 변수 대신 `pnpm shots`의 공통 옵션으로 고른다. 옵션은 `--viewport=1440x900`처럼 적어도 된다. 잘못된 값은 빌드·예제 서버를 시작하기 전에 실패한다.

| 용도 | 명령 | 찍는 범위 |
| --- | --- | --- |
| 기본 · 일반 CI | `pnpm shots --viewport 1200x735 --theme mixed --sample default` | 기존 기본 샘플 55화면: 라이트 53, 다크 `dark-topic`·`dark-note-info` 2 |
| 넓은 창 | `pnpm shots --viewport 1440x900 --theme light --sample default` | 기본 샘플 55화면 모두 라이트 |
| 다크 전체 | `pnpm shots --viewport 1200x735 --theme dark --sample default` | 기본 샘플 55화면 모두 다크 |
| 분류 샘플 | `pnpm shots --viewport 1200x735 --theme light --sample subjects` | 별도 `.sandbox/subjects-library`의 분류 10화면 |

옵션을 생략하면 첫 줄과 같다. `mixed`는 기존 다크 두 장만 유지하며, `light`·`dark`는 이름이 `dark-`인 화면까지 지정한 테마로 찍는다. CI는 첫 줄만 실행한다. 넓은 창 · 전체 다크 · 분류 샘플은 Actions 시간 한도 때문에 CI에서 찍지 않으며, CI가 초록이어도 이 범위의 시각 확인까지 끝난 뜻은 아니다.

화면을 바꾼 PR은 맥에서 해당 샘플을 **1200×735 · 1440×900 × 라이트 · 다크**로 찍어 아래 체크리스트를 직접 본다. 분류 화면을 바꾸면 `--sample subjects`도 같은 조합으로 본다. 저장 위치는 `SHOTS_DIR=shots/<샘플>-<크기>-<테마>`로 나눠 전후 그림이 서로 덮이지 않게 한다. 구조만 옮긴 L2b 화면은 동일한 샘플·크기·테마의 전후 바이트를 비교한다.

`SHOTS_PORT`·`SHOTS_SKIP_BUILD`·`CHROMIUM_PATH`·`SHOTS_DIR`은 실행 환경 설정이다. 예전 `SHOTS_VIEWPORT`·`SHOTS_SCHEME`·`SHOTS_SUBJECTS`도 호환을 위해 받지만, 같은 항목의 CLI 옵션이 우선한다. 선택 옵션 전체는 `pnpm shots --help`로 본다.

TeX CI는 `tex.yml`의 파일 변경 조건에 맞는 PR에서 기존 서버 테스트를 돌린다. `blockCompile.test.ts`와 `block-header.ts`·서식 선택·그림·본문·참고문헌·서식 파일 의존성도 조건에 포함한다. 일반 CI의 `pnpm test`는 TeX가 없으면 실제 컴파일을 건너뛴다. TeX가 걸리는 PR의 실제 컴파일은 맥에서 확인한다. `node scripts/ci/check-tex-coverage.mjs`는 실제 TeX guard(`hasLatex`)를 쓰는 테스트를 하위 폴더까지 찾고 컴파일 입력 파일·서식과 함께 변경 조건 누락을 검사한다. 새 컴파일 입력 도우미는 그 검사 파일의 `TEX_INPUT_FILES`에 더한다. 변경 조건은 일반 경로·`*`·`**`를 쓰며, 누락 검사는 지원하는 Node 22 초기 버전에서도 실행된다. 이 가벼운 검사는 `pnpm test`에 포함되며 TeX 설치·컴파일·촬영을 추가하지 않는다.

### 화면 점검 체크리스트

화면을 바꾸는 PR과 전체 점검(10/6)에서 화면마다 본다. 1200×735(두 패널) · 1440×900, 라이트 · 다크.

1. 값: 색 · 글자 크기 · 굵기 · 모서리 · 간격이 토큰인가. 색은 상태 점 · 주 버튼 · 선택 표시 · 사용자 차례(주황)에만 쓰였나. 빨강은 오류 · 지우기에만인가
2. 상태는 `StatusDot`이고 대상 툴바 맨 왼쪽인가
3. 가장 중요한 것 하나가 먼저 보이고, 큰 제목은 한 번인가
4. 고정 영역(작업 패널, 보기 전환)이 내용 길이와 상관없이 같은 자리인가
5. 툴바가 세 구역(왼쪽 무엇 · 가운데 보기 · 오른쪽 행동, 주 버튼은 맨 오른쪽 하나)인가
6. 항목 행동이 항목 오른쪽 위 아이콘이고, 좁은 칸에서는 늘 보이나
7. 글자 · 아이콘 · 기호가 눈으로 보아 가운데 맞나
8. 입력란이 평소 닫혀 있고 연필로만 열리나. 여러 칸은 고치기 창, 값 하나는 그 자리인가
9. 입력란이 한 모양이고 같은 줄 입력란 · 버튼 높이가 같은가
10. 팝업 · 메뉴가 사이드바 · 스크롤 칸에 잘리지 않나(사이드바를 켠 채 왼쪽 끝 · 아래 끝에서 열기)
11. 지우기 확인이 되돌릴 수 없을 때만이고 무엇이 남는지 적혀 있나
12. 기호만 있는 버튼에 한국어 동사 이름(`data-tip` · `aria-label`)이 있나
13. 따로 된 "…로 가기" 대신 대상 이름을 누르게 되어 있나
14. 숨은 방법(찾기 낱말, 끌어서 순서, 가리켜야 보이는 아이콘)에 보이는 단서가 있나
15. 버튼 말이 4절 표의 말이고, 영어 태그 · 자료 값이 보이지 않나
16. 칸 이름이 짧고 범위를 드러내나. 화면에 설명 글을 늘어놓지 않았나
17. 긴 목록이 찾기 먼저 · 접힘 · "n개 더 보기"인가. 긴 경로는 마지막 이름만인가
18. 카드 · 표 칸이 한 줄(넘치면 …)이고 카드끼리 줄이 맞나
19. 빈 상태가 상자 없는 한 줄이고, 라이브러리 첫 화면이 출발점을 보이나
20. 설정 절이 다른 설정과 같은 모양인가
21. 사이드바가 긴 화면 끝까지 차 있고, 끌 수 있어 보이는 경계가 실제로 끌리나
22. 좁은 폭에서 한글이 한 글자씩 세로로 끊기지 않나. 태그 · 시각 · 칩이 한 줄이고 긴 이름만 줄어드나. 덜 중요한 것부터 숨나
23. 다크에서 글자 대비, 카드 · 그림 칸 바탕, 새 토큰의 다크 값 두 곳이 맞나
24. 사용자가 쓴 글의 Markdown 목록이 • ◦ ▪로 보이나

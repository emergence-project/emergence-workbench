# 설계: 개념노트의 주장과 Lean 선언을 잇는 플러그인 (초안)

2026-11-28 · 상태: **초안, 작업 중.** 사용자 「진행」 전이라 코드는 없다 · 범위: 지식(개념노트) 화면의 오른쪽 사이드바, 내장 플러그인 하나

이 문서는 이 일을 하고 있다는 것을 저장소에서 볼 수 있게 먼저 올린 것이다. 아래 내용은 사용자가 방향만 정한 상태이고, 「미정」으로 적은 칸은 정해지지 않았다.

## 1. 왜

개념노트의 정의 · 성질을 Lean 4로 형식화하는 일을 앱 밖의 별도 Lean 저장소에서 시작했다. 노트에서는 어느 주장이 형식화됐는지 보이지 않고, Lean 쪽에서는 어느 노트의 주장인지 보이지 않는다.

사용자가 정한 방향 (2026-11-28):

- 노트 본문에는 Lean에 관한 것을 적지 않는다. 사이드바에서 확인한다.
- 노트와 Lean은 가능하면 대응시키되 1대1일 필요는 없다. 노트와 Lean을 곧바로 묶지 않고 **노트 – 앱 – Lean** 고리로 잇는다. 가운데를 맡는 것이 이 플러그인이다.
- 노트는 여러 분야로 계속 늘어나고, 영역과 역할에 따라 양식과 확인 방법(증명 · 계산 · 실험)이 달라질 수 있다. Lean은 확인 방법 가운데 하나다.

## 2. 고리

| 자리 | 가진 것 | 모르는 것 |
| --- | --- | --- |
| 노트 (지식 저장소) | 주장 글, 주장마다 영구 ID | Lean |
| Lean 저장소 | 선언, "이 선언은 주장 ID X에 관한 것"이라는 표식, 그것을 모아 내보낸 목록 파일 | 노트의 글과 파일 이름 |
| 앱 (이 플러그인) | 두 쪽을 ID로 맞춘 결과와 상태 | — |

- 주장 ID는 뜻 없는 짧은 글자다. 한 번 붙으면 바뀌지 않고, 지워진 ID는 다시 쓰지 않는다. 노트 이름이나 성질 번호를 넣지 않는다(이름 바꾸기 · 나누기 · 합치기 · 번호 다시 매기기에 연결이 끊기지 않게).
- 한쪽만 있는 것은 오류가 아니다. 주장에 Lean 선언이 없으면 「연결 없음」, Lean 표식의 ID가 어느 노트에도 없으면 「노트 없음」이다.
- 주장 하나에 Lean 선언이 여럿일 수 있고, 선언 하나가 여러 주장에 걸릴 수 있다.
- 앱은 Lean을 돌리지 않는다. Lean 저장소가 만들어 둔 목록 파일만 읽는다(CI와 내려받는 앱에는 Lean이 없다).

## 3. 첫 판의 범위

**하는 것 (셋):**

1. 개념노트에서 주장 ID를 읽는다.
2. Lean 저장소가 내보낸 목록 파일을 읽는다.
3. 개념노트 사이드바에 주장마다 상태를 보인다: 「연결 없음」 · 「진술됨」 · 「증명됨」.

**하지 않는 것 (다음 판 후보):**

- Lean 진술을 수식 글로 되읽어 주는 것, 사용자의 「진술 일치 확인」과 그 기록.
- 진술 · 노트 글의 지문과 "바뀌면 확인이 풀림".
- Lean 말고 다른 확인 방법(계산 · 실험 · 문헌)의 상태, 주장의 종류 표.
- 분류별 현황 화면, 지식 목록의 표시, MCP 도구.
- 앱이 노트에 ID를 자동으로 붙이는 것(§7 질문 2).

## 4. 읽는 것

### 4.1 노트의 주장 ID — 표식 모양 미정

정해진 것: 본문 글에 보이지 않아야 하고, 주장 글과 함께 움직여야 한다(문단을 다른 노트로 옮기면 ID도 따라간다).

후보(시험 전): 주장 덩어리 끝의 한 줄 주석 `<!-- claim:k7q2m -->`. 확인할 것은 이 저장소의 미리보기 · 편집기와 개념노트를 함께 읽는 다른 앱들이 이 줄을 어떻게 다루는지, 그리고 개념노트 「확인함」의 본문 hash다. 지금 hash는 본문 전체로 계산하므로 ID 한 줄을 더하면 확인이 풀린다. ID 표식을 hash에서 빼는 변경이 먼저 필요하다(본체 변경, 따로 「진행」).

### 4.2 Lean이 내보낸 목록 — 모양 초안

Lean 저장소에서 명령 하나가 만든다. 위치는 이 컴퓨터의 플러그인 설정에 적는다(저장소마다가 아니라 컴퓨터마다).

```json
{
  "format": 1,
  "generatedAt": "2026-11-28T10:00:00Z",
  "commit": "0123abc",
  "toolchain": "leanprover/lean4:v4.36.0",
  "links": [
    {
      "claim": "k7q2m",
      "decl": "Example.add_comm'",
      "module": "Example.Basic",
      "kind": "theorem",
      "sorry": false,
      "axioms": ["propext"]
    }
  ]
}
```

- `format`이 모르는 값이면 읽지 않고 그 사실을 사이드바에 적는다.
- `generatedAt` · `commit`은 화면에 "목록을 만든 때"로 보인다. 목록이 Lean 저장소의 지금 상태와 같은지는 첫 판에서 앱이 확인하지 못한다.
- 예제(`fixtures/`)에는 손으로 쓴 작은 목록 파일을 둔다.

## 5. 상태 계산

선언 하나의 상태:

| 상태 | 조건 |
| --- | --- |
| 진술됨 | 목록에 있다(형 검사를 통과했다). `sorry`가 있거나 표준 밖의 공리를 쓴다 |
| 증명됨 | `sorry`가 없고 쓰는 공리가 표준 셋(`propext` · `Classical.choice` · `Quot.sound`)뿐이다 |
| 정의 | `kind`가 정의다. 증명 상태가 없다 |

주장 하나에 선언이 여럿이면 첫 판은 합쳐서 판정하지 않고 선언을 줄마다 보인다(예: "Lean 선언 2 · 증명됨 1 · 진술됨 1"). 어느 선언이 그 주장을 대표하는지는 역할이 정해진 뒤에 다룬다.

「증명됨」은 Lean 진술이 증명됐다는 뜻이다. 그 진술이 노트의 주장과 같은 말이라는 뜻이 아니다. 이 구분을 사이드바의 풀이 글에 적는다. 같은 말인지 확인하는 칸은 다음 판이다.

## 6. 앱에서 만드는 것

- **이름표:** `packages/core/src/plugins/lean-link/` · id `lean-link` · `stage: 'experiment'` · `installedByDefault: false` · 규칙 목록(`docs/rules/registry.json`)에 한 줄. 연구 저장소에 쓰는 파일이 없으므로 `keeps`는 비운다.
- **서버:** 목록 파일과 노트의 ID를 읽어 맞춘 결과를 주는 읽기 전용 경로 하나. 쓰기 없음. 응답 모양은 `packages/core/src/contract/`에 둔다.
- **화면:** 개념노트 오른쪽 사이드바(문서 정보 아래)에 절 하나. 주장마다 한 줄: 상태 점과 이름, 펼치면 Lean 선언 이름과 모듈. 목록 파일이 없거나 설정이 비어 있으면 그 사실과 설정하는 곳을 한 줄로.
- **새로 여는 자리:** 플러그인 틀은 지금 프로젝트 페이지 · 사이드바 줄 · 내 차례만 열려 있다. 개념노트 사이드바의 절과 플러그인 설정 칸(경로 하나)을 새로 연다.
- **소개:** 화면을 바꾸는 PR에서 소개의 해당 절을 함께 고친다.
- **고위험 영역:** 건드리지 않을 계획이다. 건드리게 되면 그 PR은 사용자가 합친다.

화면은 만들기 전에 시안을 사용자에게 보인다.

**PR 나누기 (추정):**

1. 이름표 · 설정 칸 · 서버 읽기 경로 · 규칙 목록 한 줄 · 예제 목록 파일. 화면 없음.
2. 개념노트 사이드바의 절과 소개.
3. (본체, 따로) 개념노트 「확인함」 hash에서 ID 표식 빼기.

## 7. 정해지지 않은 것

1. 노트의 ID 표식 모양(§4.1)과, 함께 읽는 다른 앱들에 미치는 영향.
2. ID를 누가 언제 붙이는가. 후보: 에이전트가 「수정 검토」를 거쳐 제안 / 앱의 단추. 확인한 노트를 고치는 일이라 사용자 허락이 필요하다.
3. 무엇을 주장 하나로 치는가(제목 · 문단 · 글머리표). 첫 판은 ID가 붙은 덩어리만 주장으로 본다.
4. 목록 파일을 Lean 저장소에 커밋해 둘지, 그때그때 만들지.
5. 사용자의 판단 기록(일치 확인)을 어디에 둘지. 다음 판.
6. 화면의 말: 「진술됨」 · 「증명됨」 · 「연결 없음」 · 「노트 없음」.

## 8. 하지 않기로 한 것

- 노트 머리말이나 본문에 Lean 선언 이름을 적는 것(본문에 Lean을 적지 않는다는 결정).
- 주장과 선언을 1대1로 강제하는 검사.
- 앱이 Lean을 설치하거나 돌리는 것.

# 새 앱에 피드백 넣기

[피드백 규약](README.md)을 새 앱에 넣는 순서다. 모듈 번호는 규약 2절의 것이다. 단계마다 앞 단계만 있으면 쓸 수 있게 나눴다.

## 1단계: 최소 묶음 (남기고, 처리하고, 답한다)

1. **세 파일을 정한다.** 원문 · 처리 기록 · 사용자 답을 어디에 어떤 모양으로 둘지 정한다. 칸 이름은 규약 3–5절 그대로. 폰처럼 여러 기기가 쓰면 항목마다 파일 하나가 부딪히지 않는다.
2. **M5 차례를 먼저 만든다.** TypeScript · JavaScript 앱은 `packages/core/src/feedback-buckets.ts`를 그대로 옮긴다(타입 말고 가져오는 것이 없다). 다른 언어는 규약 6절대로 쓴다. 어느 쪽이든 [cases.json](cases.json)을 시험으로 돌린다. 이 파일은 고치지 않고 복사하고, 시험이 작업대 원본과 같은지도 본다.
3. **M1 남기기 · M2 원문.** 피드백 모드(부위 강조, 부위 이름은 바꾸지 않을 이름으로), 유형 고르기 필수, 가리킨 글자 · 창 · 앱 버전. 원문 고치기 · 지우기.
4. **M3 · M4.** 처리 기록 읽기, 답 단추 두 묶음과 코멘트, 내 글 고치기, 마지막 답 되돌리기. 결정을 묻는 답에 승인을, 빈 이유의 반려를 받지 않는다.
5. **M6 모아 보기.** 확인 필요 · 대기 · 완료 · 전체로 거른 한 표, 줄을 누르면 제자리에서 펼쳐지는 요약(이해한 요구 · 원인 · 처리 · 고친 이력) · 대화 · 입력란. 레일 수는 사용자 차례인 항목 수.
6. **M7 에이전트 도구.** 에이전트 차례 목록을 까닭(`comment` · `rework` · …)과 함께 보이는 읽기 전용 명령 하나. 앱의 `CLAUDE.md`(또는 `AGENTS.md`)에 그 명령과 [agent.md](agent.md)를 가리키는 줄을 넣는다.

여기까지 하면 사용자 → 에이전트 → 사용자로 한 바퀴가 돈다.

## 2단계: 쌓이면 더한다

- **M8 올리기:** 원문 · 사용자 답을 저장소에 올리는 단추와 저절로 올리기. 처리 기록과 다른 파일이라 부딪히지 않는다.
- **남길 때 화면 그림, 적던 글 보존:** 작업대 `FeedbackMode.tsx`(보이는 요소만 그림으로)와 `feedbackDraft.ts`.
- **교훈:** 처리 기록 `revised`의 `miss` · `lesson`을 세어 에이전트 도구 첫머리에 보인다(`packages/core/src/feedback-lessons.ts`).
- **M9 마무리:** 같은 지적 합치기(`merged_into`), 반영 버전과 "앱에 있음", 전후 그림, 그 자리로 가기, 승인된 것을 소개로 옮기기.

## 점검

- [ ] 유형을 고르지 않으면 등록되지 않는다
- [ ] cases.json 시험이 통과한다
- [ ] 화면 · 레일 · 에이전트 도구가 같은 차례 함수를 쓴다
- [ ] 에이전트가 처리 기록 말고는 쓰지 않는다
- [ ] 결정을 묻는 답에는 승인 단추가 없다
- [ ] 시각을 한 시간대로 적는다

# 맡긴 일의 규칙

사용자가 앱 작업 탭에서 에이전트(Claude Code, Codex 등)에게 맡긴 연구 작업에 적용하는 규칙이다. 모든 연구 프로젝트에 같게 쓴다. 각 저장소의 `workbench/STATUS.md` 맨 위 한 줄이 이 문서를 가리킨다. (2026-10-07 사용자 결정, `planning/requirements.md` §8.1 "맡긴 일과 작업 탭")

## 1. 범위

- **적용한다:** 사용자가 맡긴 계산, 유도, 문헌 대조, 문서 초안처럼 결과가 나오고 사용자가 그 결과를 판단해야 하는 일.
- **적용하지 않는다:** 사용자가 직접 하는 연구, 앱 개발(research-workspace PR), 단순 질문과 답.
- 각 저장소의 자체 규칙(AGENTS.md, CLAUDE.md, 문서 생애 절차)이 이 문서보다 앞선다. 물리·수학 내용의 승인은 각 저장소 규칙대로 사용자만 한다.

## 2. 파일 하나가 일 하나이자 보고서다

맡긴 일은 그 프로젝트 저장소의 `workbench/tasks/<날짜>-<이름>.md` 하나다. 앱이 맡길 때 만들고, 에이전트는 같은 파일에 결과를 채운다. 사용자는 앱에서 이 파일을 보고서로 읽고 판단한다. 긴 분석은 노트로 따로 쓰고 `outputs`에 건다.

### 2.1 앱이 쓰는 칸 (맡길 때)

| 칸 | 뜻 |
| --- | --- |
| `title` | 작업 이름. 보고서 제목이다 |
| `topic` | 주제 id (선택) |
| `agent` | 맡은 에이전트: `claude-code` · `codex` |
| `created` | 맡긴 시각 `YYYY-MM-DD HH:MM` |
| `state` | 아래 2.3 |
| `task` | 작업 내용 |
| `end-condition` | 종결 조건: 무엇과 대조해 어떤 기준이면 끝인지. 비어 있으면 에이전트가 먼저 제안한다(3.1) |
| `references` | 참고 자료: 먼저 읽을 노트 · 논문 · 폴더 (선택) |
| `avoid` | 하지 말 것 (선택) |

### 2.2 에이전트가 쓰는 칸 (결과)

| 칸 | 뜻 |
| --- | --- |
| `result-at` | 결과를 낸 시각 `YYYY-MM-DD HH:MM` |
| `conclusion` | 결론 한 문장. 카드와 보고서 맨 위에 보인다 |
| `end-check` | 종결 조건 통과 여부: `pass` · `fail` · `unknown` |
| `ask` | 사용자 확인 요청. 사용자가 정해야 할 것을 **질문으로** 적는다. 3개까지. 고를 것이 예/아니요가 아니면 `{ q: 질문, options: [가, 나] }` |
| `issues` | 남은 문제. 결론을 바꿀 수 있는 것부터. `{ text, impact, next }` (`impact`: "결론의 숫자를 바꿀 수 있음" · "결론과 따로", `next`: 이어지는 다음 지시 번호) |
| `next` | 다음 지시 제안. `{ task, end-condition }`. 사용자가 승인하면 그대로 새 작업이 된다 |
| `outputs` | 산출물: 결과가 만든 파일 · 데이터 폴더 · 커밋 |
| `check.machine` | 기계 검증: 돌린 검사와 결과 한 줄 |
| `proposal` | 종결 조건 제안 `{ end-condition: [..], reason }` (3.1) |

머리말은 YAML이다. `{ … }` 안의 글에 쉼표나 콜론이 들어가면 따옴표로 감싸거나 줄을 나눠 적는다(감싸지 않으면 쉼표에서 글이 잘린다).

본문은 두 절이다: `## 요약과 결론`(결론을 쉬운 말로 두세 문장)과 `## 근거`(방법 몇 줄, 핵심 그림, 산출물). 확인하지 않은 해석이나 어림은 "추정"이라고 적는다.

### 2.3 상태 (`state`)

| 값 | 앱 표시 | 누가 바꾸나 |
| --- | --- | --- |
| `working` | 진행 (파랑) | 앱: 맡길 때, 수정 요청, 종결 조건 승인 |
| `proposed` | 종결 조건 승인 대기 (사용자 차례 주황) | 에이전트: 종결 조건을 제안했을 때 |
| `result` | 판단 대기 (사용자 차례 주황) | 에이전트: 결과를 다 채웠을 때 |
| `done` | 해결 (청록) | 앱: 사용자가 승인 |
| `paused` | 멈춤 (주황) | 앱: 사용자가 멈춤으로 둠 |
| `stopped` | 폐기 (회색 고리) | 앱: 사용자가 폐기 |

에이전트는 `done`을 쓰지 않는다. 결과를 만든 세션은 그 결과를 승인하지 않는다.

### 2.4 앱이 쓰는 칸 (판단)

- `answers`: 확인 요청에 대한 사용자 답 `{ n, answer, note, at }`. 다음 일을 하기 전에 읽는다.
- `judged`: 판단 기록 `{ at, verdict, note, seconds }`. `verdict`는 `approve` · `send-back`(수정 요청) · `pause` · `discard`. 마지막이 `send-back`이면 `note`가 고칠 것이다. `seconds`는 판단에 쓴 시간이다.
- `check.human`: 승인한 시각.

## 3. 에이전트가 할 일

### 3.1 종결 조건을 먼저

`end-condition`이 비어 있으면 일을 시작하지 않는다. `proposal`에 종결 조건과 이유를 적고 `state: proposed`로 둔다. 사용자가 승인하면 앱이 `end-condition`으로 옮기고 `state: working`으로 돌린다. 그때 시작한다.

### 3.2 일하는 중에 종결 조건을 바꾸지 않는다

맞지 않으면 멈추고 `proposal`로 새 조건과 이유를 적는다. 스스로 바꾼 기준으로 끝냈다고 하지 않는다.

### 3.3 결과를 채우고 판단을 넘긴다

2.2의 칸과 두 절을 채우고 `state: result`로 둔다. 확인 요청이 없으면 `ask`를 비운다.

제출 전에 research-workspace 폴더에서 다음 읽기 전용 검사를 통과시킨다:

```sh
pnpm agent:check-tasks <연구 저장소 폴더>
```

저장소 폴더 대신 그 안의 `workbench` 폴더도 받는다. 다른 폴더에서 부를 때는 `pnpm --dir <research-workspace 폴더> agent:check-tasks <연구 저장소 폴더>`로 실행한다. 명령은 파일을 쓰지 않고, 작업 파일 이름·YAML·필수 칸(`title`·`task`·`state`)·상태 이름·종결 조건 제안·질문·다음 지시·판단 기록의 형식을 검사한다. 오류가 없으면 종료 값 0, 있으면 파일과 줄을 보이고 종료 값 1이다. 상태를 자동으로 `working`으로 바꾸지 않는다.

깨진 파일은 앱의 ‘맡긴 일’ 목록과 `pnpm agent:status`의 ‘작업 파일 오류’에 남는다. 정상 작업은 계속 보이고, 오류 파일은 판단하거나 답을 쓰기 전에 원문을 고쳐야 한다. 제안 상태(`proposed`)에는 `proposal.end-condition`의 비어 있지 않은 글 목록이 필요하다. 질문(`ask`)은 글 또는 `{ q, options }` 목록으로 3개까지 적는다. YAML 오류 줄의 콜론·쉼표를 먼저 확인한다.

`pnpm agent:status <연구 저장소 폴더>`는 멈춘 연구노트·계산 노트의 본문 경로와 `note.yaml`에 적힌 `resume`도 함께 보여 준다. 보조 노트의 멈춤·재개 조건은 기존 작업노트 절에만 나온다.

### 3.4 정정은 지우지 않는다

앞서 낸 결론이 틀렸으면 지우지 않고 "정정" 또는 "철회"와 날짜, 이유를 본문에 남긴다. 결과에 쓰인 스크립트만 남기고 `outputs`에서 가리킨다.

### 3.5 대기가 쌓이면 검토를 돕는다

한 프로젝트에서 판단 대기(`result`·`proposed`)가 3건을 넘으면 새 일을 스스로 늘리지 않는다. 대기 중인 결과의 요약이나 확인 요청을 다듬어 검토를 돕는다. 사용자가 새로 맡기면 그대로 따른다. 2주 넘게 판단 대기인 일은 닫기 · 보관 · 계속 중 무엇으로 할지 사용자에게 묻는다.

## 4. 사용자가 하는 일 (앱)

- **승인**(동그라미 체크): 결과는 해결로, 종결 조건 제안은 그 조건으로 시작.
- **수정**(동그라미 되돌림 화살표, 10/9까지 이름 "수정 요청"): 고칠 것 한 줄과 함께 진행으로 돌린다. 그만둘 일이면 "하지 마".
- **⋯ 메뉴**: 멈춤으로 두기, 폐기.
- **확인 요청에 답하기**: 고르는 즉시 `answers`에 적힌다. 승인과 따로다.
- **다음 지시**: 제안마다 승인(그대로 새 작업), 고치기(채워진 맡기기 창), 빼기.
- **에이전트 깨우기**: 앱은 에이전트를 직접 돌리지 않는다. 맡긴 뒤 · 종결 조건을 승인한 뒤 · 수정 요청 뒤 알림의 "에이전트에게 줄 말 복사"(진행 중인 일은 보고서 ⋯ 메뉴에도)를 눌러, 그 프로젝트 폴더에서 연 Claude Code나 Codex에 붙여 넣는다. 복사되는 말: `<작업 파일>에 맡긴 일을 해 줘. 먼저 이 파일과 규칙 문서 <이 문서>를 읽고, 결과는 같은 파일에 채워.`

판단을 기다리는 일(`result`·`proposed`)은 확인이 필요한 노트와 함께 레일의 프로젝트 수와 홈의 "확인 필요" 점에 더해진다(툴팁에 내역).

판단할 때마다 앱이 그날 일지(`workbench/log/날짜.md`)에 `판단 · <제목> · <승인 등> · <분>` 한 줄을 남긴다. 판단 한 건에 드는 시간과 되돌린 비율은 이 기록으로 센다.

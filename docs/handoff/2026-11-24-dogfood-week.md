### 2.4 명령 분류기 (`claude/week-fix-classifier`)

모두 함수를 직접 불러 재현하고 테스트(`묻지 않고 지나가던 꼴 (11/24 검토)`)를 붙였다.

- 작은따옴표 안의 `$(` · 백틱 때문에 뒤따르는 명령이 가려져 "읽기"로 판정됨 → `maskLiteral`.
- `git -C <폴더> clean|push …`처럼 전역 옵션이 끼면 하위 명령을 못 읽음 → `gitArgs`. `-c` · `--config-env`가 있으면 적어도 "실행".
- `find -exec … + …`에서 홀로 선 `+`를 끝으로 봄 → `{} +`만 끝.
- 붙여 쓴 짧은 옵션(`sed -Ei`, `tree -ao`, `git grep -lO`, `ps -axE`), `>&2file`(파일 쓰기).
- 비밀 경로 검사가 명령 전체 글에만 걸려 `cat .env`가 지나감 → 낱말마다 검사.
- `APP_OWNED` · `CRITICAL`의 `git push`가 전역 옵션을 건너뛰지 못함. `FROZEN_INSTALL` 정규식이 긴 옵션 줄에서 몇 초 걸림.

### 3.5 결정 필요 (11/26에 가려낸 것)

버그라기보다 동작을 어느 쪽으로 정할지의 문제라 고치지 않았다. 관리자에게 선택지와 추천을 따로 정리해 전했다. 정해지면 그때 고친다.

- 분류기: 값을 알 수 없는 변수를 옵션 · 경로 자리에서 무겁게 볼지, 과하게 잡는 것(위 목록)을 어디까지 풀지, 판정에 작업 한도를 둘지(감싸 돌리기 18겹에 4초, 치환 40겹), 셸 글 읽기를 문법 파서로 바꿀지, 중앙의 `gh pr create --body-file`.
- 중앙 · 피드백: 요약 뒤 메모 · 안내를 다시 붙일지, 다른 컴퓨터 대화의 중재 요청을 서버의 중앙이 받을지, 돕는 맥에 보낸 것이 닿지 않았을 때 다시 보낼지.
- 기기: 꺼진 컴퓨터의 「로그아웃 대기」를 서버가 아닌 컴퓨터에서도 보일지(답에 칸을 더하면 옛 버전이 못 읽는다), 화면이 서버보다 새 버전일 때 넘긴 요청.
- 화면: 크게 본 창을 보낸 뒤에도 열어 둘지, 터미널 갈래, 손으로 한 새로 고침에서 초안 남기기, 검색어 · 필터를 「적던 글」로 세는 것, 새 브라우저의 첫 다시 읽기.

이번에 본 불안정한 검사 (변경과 닿지 않는 실패가 세 번, 다시 돌리면 통과): `agentCentralReview.test.ts`의 「검토자는 바뀐 코드와 장부만 받는다」(곁 질문이 한 번 더 온 것으로 셈), 윈도우 확인의 「Codex를 받아 실행함」, 브라우저 검사의 `restart-reload-waits-for-kept-draft`가 8분 반 멈춤(원인 미상. #708로 사례마다 90초 한도를 두어 다시 나오면 어느 사례인지와 그림이 남는다).

분류기를 고칠 때의 교훈 (11/26, #711): 판정을 "더하기만" 해도 가벼워질 수 있다. 값의 표에 값을 더하면 넣어 볼 짝의 곱이 한도를 넘어 원래 보던 짝을 못 본다. 낱말 묶음(`alternatives`)을 늘리면 감싸 돌리기가 겹칠 때마다 곱해져 판정 시간이 터진다. 더할 때는 원래 판정의 표 · 한도와 따로 두고, 맨 바깥에서만 늘린다.

- **수**: 사이드바 「기록」과 「흐름」이 같은 흐름을 두 번 센다. 기록 화면 탭 「내 차례」는 할 일까지 넣어 사이드바 수와 다르다.

- **메모의 @**: 문장 속에 홀로 있는 `@`(예: `@ 300K`)가 기본 에이전트 부르기가 되고, `@이름에게` · `@이름야` · `@모두에게`처럼 조사가 붙으면 불리지 않는다(`calledAgent` · `mentionsOf`). 설계대로라 손대지 않았다.
- **예제 피드백**의 답 문구가 옛 말이다("하자", "승인하면 만든다").
- **접근성**: 피드백 화면의 자동 처리 스위치에 이름이 없다. 아이콘 단추 · 탭 몇 곳이 툴팁 글을 `aria-label`로 쓴다.
- **끝난 메모의 상태 줄**이 본문 뒤에 빈 줄 없이 붙는다.
- **예제 모드**: 서버 파일을 고쳐 백엔드가 다시 뜨는 동안 502와 웹소켓 오류가 잠깐 보인다.

### 6.1 검토가 찾은, 전부터 있던 구멍 (#720에서 막음)

`gh` 읽기를 가볍게 보는 변경(#721)을 검토받다가, 그 변경이 믿고 쓴 중앙의 규칙(`ghReads`)에서 나왔다. 중앙 대화가 묻지 않고 돌릴 수 있었다.

- `gh api repos/o/r/issues -f title=x -p -XGET`: 값을 받는 옵션의 값을 메서드로 읽어 POST가 읽기로 지나감.
- `gh pr -r view merge` · `gh repo -r view create 이름 --public --push`: 사이에 낀 옵션이 다음 낱말을 값으로 삼켜 다른 하위 명령이 돎.
- github.com이 아닌 호스트로 가는 `gh`(`-R 호스트/주인/저장소` · `-cR …` · `repo view -b -b 호스트/…` · 주소 · `git@…`), `--web=true`, `-F k=@파일`.
- `cat f | uniq - out.sh`: 둘째 이름에 쓰는데 읽기였음.

### 6.2 남은 것

- **#722가 놓치는 꼴** (main과 같은 판정): `IFS= read -r x`처럼 앞말이 붙은 `read`, 히어독 본문의 따옴표에 가려 다른 읽기에서만 보이는 명령, `git log --grep -- $x`, zsh의 `$=x` · `$~x`, `${x:+$y}`, 조건에 따라 넣는 값(`: || x=a`), `git`에 넘기는 치환, `sh -c` · `$( )` 안.
- **#722가 괜히 묻는 꼴**: 낱말 맨 앞의 셈과 치환(`sed -n "$((n-5)),$((n+5))p" f` · `find "$(pwd)" -name x`), 글자 그대로인 값을 `export`한 변수, `find -depth` 뒤, `git log -n $n`.
- **#720 뒤 중앙이 막는 읽기**: 주소로 시작하는 낱말은 옵션의 값이어도 막는다(`gh pr list --search https://…` · `-R https://github.com/o/r`). `gh api graphql`의 변수(`query($x: …)`)는 전부터 막힌다.
- **전부터 있고 손대지 않은 것**: 읽기 전용 대화에서 실행을 늘 허용하면 `touch y; ./run.sh`가 지나간다(편집이 실행 뒤에 가려짐). 중앙의 `gh pr create --body-file <폴더 밖 파일>`(3.5의 결정 항목).
- **크게 본 창의 답 초안**: 사용자가 진행을 골랐지만 같은 파일을 고치는 #671이 열려 있어 시작하지 않았다. 계획: 초안은 항목마다 하나, 적는 동안 본 그림을 모두 붙인다(「전 · 후 그림:」).
- **결정 필요가 새로 나옴**: (1) 한 맥의 TeX(작게 깐 것)에 서식이 쓰는 패키지 18가지가 없어 그 맥에서는 PRL · PRB · 연구노트 서식이 컴파일되지 않는다. (2) 개인 저장소의 피드백 처리 기록에 화면 구역이 없는 항목과 모르는 실수 분류가 있어, 그 기록을 검사하는 테스트 2개가 그 맥에서 실패한다. (3) 따옴표 안의 찾을 말을 경로로 보는 것은 실제 명령 1,576줄 가운데 6줄뿐이라 풀지 않기를 추천했다.
- **답을 기다리는 개선**: 메모의 @(자동완성으로 바꾼 시안), 예제 피드백의 옛 말, 접근성, 끝난 메모의 상태 줄.

### 6.3 분류기 변경에서 배운 것

- 가볍게 보는 새 규칙이 전부터 있던 규칙을 믿고 쓰면 그 규칙의 구멍이 그대로 회귀가 된다. 그 규칙부터 조이는 PR을 먼저 낸다.
- 옵션은 표를 두고 차례로 읽는다. 「앞 낱말이 값을 받는 옵션이면 건너뛴다」는 겹쳐 적으면 뚫린다.
- 한 줄의 판정은 하나다. 가운데 등급을 새로 만들면 `gh pr view 1; sh f`가 통째로 그 등급이 되고, 「외부」로 올리면 읽기 전용 대화가 막던 편집 · 삭제를 묻는 것으로 풀 수 있다. 무게가 아니라 대화 종류마다의 판정(허용 · 묻기 · 막기)으로 비교한다.
- 생성한 명령의 비교와 실제 셸 검사(가짜 프로그램)는 매번 0건이었지만 별도 검토는 `gh` 쪽에서 네 번 연속 실제 문제를 찾았다. 검토가 프로그램의 `--help`로 따로 만든 모형과 대조한 것이 컸다. 검토를 반영한 뒤에도 다시 검토한다(반영하다 새 회귀를 만든 적이 있다).
- 판정 변화는 실제 명령으로 잰다. 「자주 걸린다」고 어림한 꼴이 재 보니 0.6%였다.

# Agent entry point (MCP)

[한국어](agent-mcp.ko.md)

Agents such as Claude Code and Codex read Emergence Workbench projects, notes, records, delegated tasks and concept notes **through the app server**. The MCP tools do not open files directly: they use the same API as the screen, so they see the same content and the same hashes. The write tools are `edit_note` and `edit_concept`, which change notes, `answer_record` (10/15), which answers a question or instruction record, `add_record` (10/15), which leaves a question or memo for the user under the agent's name, and `add_task`, `report_task` and `add_journal` (10/21), which create a task, write a task's proposal or result, and add a line to today's journal. Agents use these instead of reading `workbench/STATUS.md` or editing workbench files: the outputs are short and the work shows up in the app (10/21: agents in the research repositories were reading the 40KB STATUS.md and editing task and journal files by hand). The edit tools work like this: the agent writes at once, the app keeps the text before the edit as a baseline, and the user approves, reverts or edits each changed paragraph on the edit review screen (a project's "Edit review" section `#/r/<project>/edits` for research notes, `#/review` for concept notes). Notes the user has reviewed need the user's permission in the conversation first. Each edit records which agent made it, from the name the client sends when it connects (`clientInfo.name`: Claude Code → `claude-code`, Codex → `codex`, others as sent). The name is what the client says about itself and is not checked. Files an agent changes directly, without the app, leave no such record; for those, see the commit author. Edits made through the app are also committed under the agent's name (11/10): if the file had no uncommitted human changes before the edit, the app commits just that file as the agent (Claude, Codex or Gemini, `<name>@agents.emergence-workbench`) and pushes it (`apps/server/src/agentCommit.ts`). A file that still had human changes is not committed, so authorship never mixes; it goes up with the next human push. In the review the user can ask about a changed paragraph: the question is saved as a note record with `edit: 질문` or `edit: 수정` (`docs/repo-format.md` §6.2). The app asks Claude on the Mac right away; when that is not available the record stays unanswered and shows up in the agent's queue. For `수정`, revise the paragraph with `edit_note`, then answer the record with `answer_record`.

## Before you start

- The app server must be running on the Mac (the installed service, default `http://127.0.0.1:5174`). If it is off, every tool answers "Cannot reach the Emergence Workbench app server" and does nothing.
- To use a server at another address, set `RW_URL`. For sample mode (`pnpm dev`): `RW_URL=http://127.0.0.1:8130`.
- The installed app (downloaded installer) picks a new port and a one-time key every time it opens, and its server refuses requests without the key. The MCP entry finds both in `server.json` in the app's settings folder, so agents registered outside the app need no change. Agents the app starts itself get them as `RW_PORT` and `RW_KEY`.

## Register it

In the app, Settings › Agents › Connections has a **Connect** button per agent (11/8): for the Claude app (desktop) it adds one `emergence-workbench` entry to `claude_desktop_config.json` (macOS `~/Library/Application Support/Claude`, Windows `%APPDATA%\Claude` or the Store app's `LocalCache\Roaming\Claude`; other entries are kept, an unreadable file is left alone), and for Claude Code and Codex it runs their `mcp add` (`POST /api/setup/agents/:key/register`, `mcpRegister.ts`). The entry is the app's own node and `scripts/mcp.mjs`, so a computer without Node works too. The Mac installer (`zsh scripts/install.sh`, [mac-setup.md](mac-setup.md)) registers Claude Code and Codex for you. To do only this step, run `pnpm agents:register` (`scripts/register-agents.sh`: skips what is registered, re-registers when the app folder moved). By hand, put the path of the app folder in `<app folder>`. Nothing is added to your research repositories (user-scope registration).

**Claude Code**

```sh
claude mcp add --scope user emergence-workbench -- node <app folder>/scripts/mcp.mjs
```

Settings › Accounts › Agent connection shows this line with the real app folder (copy button) and when an agent last called the app: the MCP tools send an `x-rw-agent` header with the agent name, and the app keeps the last call in `agent-seen.json` in the settings folder.

**Codex** (`~/.codex/config.toml`)

```toml
[mcp_servers.emergence-workbench]
command = "node"
args = ["<app folder>/scripts/mcp.mjs"]
```

Inside the app folder, `pnpm mcp` also starts it (it speaks MCP over stdio, so you never type into it).


## Tools (read-only except new_note, edit_note, edit_concept, answer_record, add_record, problem_propose, problem_prepare, attempt_add, attempt_start, attempt_report, attempt_verdict, direction_report, add_task, report_task, checkpoint_task, add_journal and changes_since, which only moves its own baseline)

When it connects, the server tells the agent which tools to use in which order for each kind of job (`INSTRUCTIONS` in `apps/server/src/mcp.ts`): start with `rules`, then `overview`, then `project_status`, then `changes_since`. If you add or rename a tool, update that order too; `mcp.test.ts` checks that every tool name there exists.

## Rules it keeps

- To change a note or concept note, prefer `edit_note` / `edit_concept`. For other writes, call the app server API (`GET /api` gives the main routes and how to use them, `GET /api?all=1` every route) and send the hash you read as `baseHash`. If the file changed in the meantime, the write is refused with 409. Creating, appending and one-field changes take no hash, and journal edits send the entry's current text as `was`; `GET /api` and `docs/repo-format.md` §12 list them.
- You may also edit repository files directly, including when the app server is stopped: tell the user when it cannot be reached, follow `docs/repo-format.md`, and run `pnpm --dir <app folder> agent:check <repository>` afterwards. Notes and concept notes the user has reviewed still need permission in the conversation; manuscripts are edited only when the user asks. Locked concept notes are never changed.
- Instructions (지시): Settings › Agents chooses whether Claude on the Mac carries them out itself, right away or once a day at a chosen time (default: no, an agent session picks them up). It runs one at a time with read-only tools and answers as `claude`, with note changes as fix blocks the user applies. Records it already answered are no longer in `unanswered`.
- Check pending edits with `list_edit_reviews` or the project summary. Do not reintroduce paragraphs the user reverted. Reverting an agent edit to a project note appends a status record to that project’s journal; concept notes have no project journal, so their reverts are not recorded there.
- Each research repository's own `AGENTS.md` and `CLAUDE.md` come before this entry point.
- Code: `apps/server/src/mcp.ts` (tools), `scripts/mcp.mjs` (stdio start), tests `apps/server/src/mcp.test.ts`.

## Conversations the app starts (agent chats, 10/21)

The app can also start Claude Code on the Mac itself (Claude Agent SDK, `apps/server/src/agentChats.ts` · `agentRunner.ts`, API `/api/agent-chats`). Each conversation belongs to one project and has a scope (the project, one topic or one note) and a write level (read only, or notes and records). The same MCP tools are attached in-process, and the app decides every tool call:

- Reading the project, the shared library and other registered projects is allowed; reading outside the scope shows as "outside the scope" in the conversation. Reading other folders asks the user.
- Files cannot be written directly (`Write`, `Edit` …). Notes change only through `edit_note`, so they land in edit review. Changes outside the scope, to another project or to concept notes are refused, and the agent is told to say what should change instead.
- While a conversation changes a note it holds that file; another conversation cannot change it until the turn ends. `GET /api/agent-work` lists running conversations and the files they hold.
- Commands, web access and unknown tools ask the user (an approval card); "always" covers only the same command in that conversation, and the always-list can be cleared one by one (`POST /api/agent-chats/<id>/forget`).
- Permissions are one setting per conversation (`mode`, with `write`): read only · ask before edits (every note edit asks too) · accept edits · plan mode (SDK plan mode; note edits are refused until the user approves the plan card for `ExitPlanMode`). Model and thinking (`low` · `medium` · `high` · `xhigh` · `max`, only those the model takes) can change mid-conversation (`POST /api/agent-chats/<id>/settings`) and apply from the next turn. The models offered come from the Mac's Claude Code, with versions (`GET /api/agent-chats/models`: the aliases `default` · `opus` · `sonnet` · `haiku` and ids such as `claude-opus-5`, the real model `resolved`, the thinking levels it takes; asked without a prompt and kept for 30 minutes, empty when Claude Code cannot start). `default` is that account's Claude Code default (user settings are not read).
- A message can carry attachments (`attach`: note, topic, file, selection, paper, record; the agent reads those first) and up to four images. A message sent while the turn runs waits and starts the next turn. `TodoWrite` shows as one to-do card per turn, and every allowed `edit_note` as an edit card (+/−, link to edit review); the conversation keeps `todos` and the changed files.
- At most two conversations run at once; the rest wait in a queue. Repository and user settings of Claude Code (hooks, allow rules) are not loaded. Conversations are stored in the app's config folder (`agent-chats/<id>.json`), not in the research repository.

### Codex and Gemini in app conversations (2026-10-30)

A conversation can be handed to Codex or Gemini instead of Claude (`agent` in `POST /api/agent-chats`, fixed for the conversation). The app starts the CLI installed on the computer over the Agent Client Protocol (ACP, JSON-RPC on stdio; `apps/server/src/agentAcp.ts`): `gemini --acp`, and `codex-acp` (`@agentclientprotocol/codex-acp`; the older `@zed-industries/codex-acp` works too) for Codex. The app built by `scripts/bundle-app.mjs` carries the connector (`vendor/codex-acp`, Apache-2.0) and runs it with its own node, passing the codex the app downloaded for "Connect ChatGPT" as `CODEX_PATH` (11/8: a friend's Windows computer has no Node or npm). The app running from the repository downloads the same pinned connector (`apps/server/src/codexAcp.json`, SHA-512 checked) into its config folder `codex-acp/` after "Connect ChatGPT" or when a Codex conversation first opens (`codexAcp.ts`), so Codex needs no `npm i -g` there either and uses the same codex and sign-in as ChatGPT answering questions. Both keep their own sign-in. `GET /api/agent-chats/agents` says which are installed and signed in, `GET /api/agent-chats/models?agent=codex|gemini` lists their models (from `session/new`, kept 30 minutes).

- The agent's permission requests (`session/request_permission`) are mapped to the Claude tool names (`Bash`, `Edit`, `Write`, `Read`, `WebFetch` …) and go through the same decision as Claude conversations.
- The same MCP tools are attached as an HTTP server that exists only while the conversation runs (`POST /api/agent-mcp/<random key>`, `agentMcpHttp.ts`). Every `tools/call` goes through the conversation's decision first, so read-only, scope, held files and edit review hold even when the agent does not ask.
- Codex runs research conversations in its `read-only` mode (writes and network ask; notes change through the app tools) and app conversations in `workspace-write` (`auto` in the older connector: writes inside the work folder). Gemini keeps its default mode (edits, commands and web ask).
- Claude only: plan mode (Codex and Gemini conversations use "ask before edits"), rewind, the explore subagent and background commands. Resuming uses `session/load` when the agent supports it.

## Status hooks (2026-10-30)

Settings › Agents › Status reports lets Claude Code and Codex running in a terminal tell the app their state without calling the MCP tools. Turning it on adds one hook command per event (`UserPromptSubmit` → working, `Notification` → waiting for the user, `Stop` → turn done, `SessionEnd` → removed) to `~/.claude/settings.json`, and a `notify` line (turn done) at the top of `~/.codex/config.toml`. Codex takes only one `notify`, so an existing one-line `notify` array moves after `--` in the app's line; the script calls it with the same arguments after reporting, and turning it off restores the original line. The command runs `<config folder>/agent-hooks/emergence-workbench-hook.sh`, which reads the server address from `endpoint.env` (rewritten each time the server starts) and posts the event to `POST /api/agent-hooks`; it does nothing when the app is off. Turning it off removes only the lines the app added (recognized by the script name). The app keeps the last state per session in memory for 12 hours (`GET /api/agent-hooks`). Conversations started in the app do not load user settings, so they never report here.

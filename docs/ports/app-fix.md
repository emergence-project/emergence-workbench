# 에이전트가 앱 고치기 옮기기

## 무엇

앱 안의 에이전트 대화 하나가 앱 자신을 고친다. 대화는 앱 저장소의 따로 둔 작업 폴더(git worktree)에서 고치고 스스로 시험하며, 올리기 · PR · CI 기다리기 · 합치기는 앱의 정해 둔 코드가 한다. 새 버전으로 다시 시작하는 것은 앱이 쉬는 틈이나 사람이 한다. 피드백 항목은 맡음 표시를 먼저 올리고 맡아 다른 컴퓨터 · 클라우드와 겹치지 않는다. 자세한 동작은 소개 › 에이전트와 안전 › 에이전트가 앱을 고치는 길(위 `about:`)이 정본이다.

## 먼저 있어야 하는 것

1. **피드백**([feedback.md](feedback.md), 규약 [../feedback/README.md](../feedback/README.md)): 무엇을 고칠지가 들어오는 길이다. 피드백 없이 「앱 수정」 대화만 열어도 되지만, 맡기 · 처리 기록 · 합치기 설정은 피드백에 붙어 있다.
2. **에이전트 대화**([agent-chat.md](agent-chat.md)): 차례 · 허락 카드 · 기록 · 다시 켰을 때 이어 가기. 앱 고치기는 그 위에 「작업 폴더가 있는 대화」 한 종류를 더한 것이다.
3. **CI 또는 그에 맞먹는 검사**: 합치기의 조건이 "마지막 커밋의 검사가 모두 초록"이다. GitHub Actions가 없으면 PR에 상태(check)를 남기는 검사 스크립트가 있어야 한다.

## 앱과 상관없는 것 (그대로 옮긴다)

| 규칙 | 까닭 |
| --- | --- |
| 대화마다 origin/main에서 새 브랜치와 worktree. 실사용 앱 폴더는 건드리지 않는다 | 사람이 고치던 파일 · 도는 앱을 깨지 않게. 대화끼리도 서로의 파일을 덮지 않는다 |
| 에이전트의 `git push` · `gh pr` · `gh api` · 서비스 명령 · `git worktree`는 막고, 앱 도구 셋(올리기 · CI 보기 · 합치기)만 준다 | 올리는 길 · PR 제목 · 합치는 조건이 언제나 같은 코드를 지난다 |
| 올리기 전 빠른 검사, 떨어지면 커밋을 풀고 오류를 대화에 돌려준다 | CI에서 떨어져 한 번 더 오가는 일을 줄인다 |
| CI 기다리기는 도구 안에서 (최대 10분) | 에이전트가 sleep · 되풀이 질문으로 차례를 쓰지 않게 |
| 합치기는 마지막 커밋의 검사가 모두 끝나 초록이고 main과 부딪히지 않을 때만, squash | 빨간 PR · 오래된 PR이 들어가지 않게. 커밋 하나 = 업데이트 하나 |
| 피드백 대화의 PR은 설정대로 앱이 합친다(CI 초록이면 · 승인한 뒤 · 늘 내가) | 사용자가 확인 수준을 고른다 |
| CI가 빨가면 실패 기록 끝부분을 그 대화에 다시 보낸다, 두 번까지 | 고칠 기회를 주되 끝없이 돌지 않게 |
| 피드백을 맡기 전에 맡음 표시를 공유 저장소에 올리고, 세 시간 뒤 저절로 풀린다 | 두 컴퓨터 · 클라우드가 같은 항목을 함께 답하지 않게 |
| 아직 합치지 않은 다른 앱 PR이 고친 파일은 고치지 못한다 | 합칠 때 부딪히지 않게 |
| 끝난 대화(PR을 합쳤거나 보관한 것)의 작업 폴더와 브랜치는 앱이 저절로 치운다. 치워도 되는지는 대화의 표시가 아니라 git에서 본다: 올리지 않은 고침이 없고, 커밋이 모두 main이나 끝난 PR에 있을 때만. git에 없는 산출물(시안)은 먼저 옮겨 둔다 (11/25) | 대화를 지울 때만 치우면 폴더(대부분 의존성)와 브랜치가 대화 수만큼 쌓인다. 표시는 낡을 수 있다(합친 뒤 같은 브랜치로 PR을 다시 연 대화) |
| 다시 시작은 사람 또는 앱이 쉬는 틈. 다시 켜진 뒤 돌던 대화는 같은 세션으로 이어 간다 | 일하던 대화를 끊지 않게 |
| 허락: 「수동」이면 고치기 · 명령 · 올리기 · 합치기를 하나씩 묻는다. 강제 푸시 · reset --hard · main 지우기는 허락해도 막는다 | 되돌리기 어려운 것은 사람 손을 거치게 |

## 옮기는 순서

1. **작업 폴더.** 「앱 수정」 대화를 열면 worktree와 브랜치(`claude/app-<id 끝 8자>`)를 만들고 의존성을 깐다. 대화 실행기의 작업 폴더를 그것으로 준다.
2. **명령 막기와 도구 셋.** 허락 판정에 `APP_OWNED`와 같은 정규식을 두고, MCP(또는 앱 도구)로 `app_submit` · `app_checks` · `app_merge`를 붙인다. 이 대화에서만 붙인다.
3. **빠른 검사.** 그 앱의 짧은 검사(형식 검사, 문서 동기화 등)를 `LOCAL_CHECKS`처럼 표로 두고 올리기 전에 돌린다. 몇 분 넘는 검사(전체 시험 · e2e)는 넣지 않고 CI에 둔다.
4. **합치기 조건.** `merge` 앞에서 검사가 모두 끝나 초록인지, main과 부딪히지 않는지 다시 본다. 에이전트가 말한 것을 믿지 않는다.
5. **피드백 잇기.** 맡기 버튼 → 맡음 표시 올리기 → 대화 열기(첫 지시에 피드백 글 · 부위 · 그림). 1분 돌보기로 CI 다시 보내기 · 설정대로 합치기를 붙인다. 첫 지시가 읽으라고 가리키는 파일(개인 규칙과 그 폴더)은 묻지 않고 읽게 둔다(`personalReadable`, 기계 설정 · 대화 기록 폴더는 빼고, 쓰기는 그대로 막음). 안내와 읽기 허락이 어긋나면 아무도 답하지 않는 허락 카드에 대화가 멈춘다(11/23).
6. **반영.** 앱 업데이트가 main을 받아 빌드하고, 쉬는 틈에 다시 시작한다. 다시 켜진 뒤 돌던 대화를 이어 간다(agent-chat.md 6단계).
7. **작업 폴더 치우기.** 정해 둔 간격으로 끝난 대화(합침 · 보관)의 작업 폴더를 돈다. 대화가 일하는 중이거나 에이전트가 그 폴더에서 열려 있으면 건너뛰고, `git status`가 비었는지(따로 남기는 산출물 폴더는 빼고)와 폴더의 끝 커밋이 main이나 끝난 PR의 끝 커밋에 들어 있는지(squash로 합치면 main의 조상이 아니므로 PR과 견준다)를 본 뒤에만 지운다. 열린 PR이 있으면 둔다. 지우기로 정한 뒤 끝날 때까지는 그 대화의 `prepare`가 기다리게 하고, 치운 대화를 이어 쓰면 origin/main에서 새로 만든다. 폴더가 없어도 되는 것(합쳤는지 묻기 · CI 그림 받기)은 앱 저장소에서 묻는다. 대화 화면이 보여 주는 시안처럼 git에 없는 파일은 치우기 전에 폴더 밖으로 옮기고, 보여 주는 길(`routes/agentMockups.ts`)이 두 곳을 함께 읽는다.
8. **화면 그림 크기.** 대화 환경(`appEnv`)에 그림 포트와 함께 `SHOTS_SCALE=1`을 주어 에이전트가 찍는 그림을 반 크기로 한다. 읽은 그림은 대화 맥락에 남아 금방 차기 때문이다(11/23). 전후 그림은 CI 산출물(2배)에서 가져오므로 그대로다.

## 다른 앱도 고치기 (11/20)

한 앱이 옆 저장소의 다른 앱도 고칠 수 있다. `appWorktree.ts`의 `AppProfile`(이름 · 빠른 검사 표 · 소개 조각을 적는가 · 그림 워크플로 · 안내 줄)을 앱마다 두고, `otherApps()`가 앱 저장소 옆에 그 폴더(`.git`이 있을 때)를 찾는다. 대화 범위 `{ kind: 'app', app: '<id>' }`가 어느 작업 폴더 · 검사 · 안내를 쓸지 고르고(`agentChats.ts` `workOf`), 파일 겹침은 같은 앱의 대화끼리만 본다. 옮길 앱에서는 다른 앱마다 프로필 하나를 더하면 된다: 빠른 검사는 몇 초짜리만, 긴 검사는 그 앱의 CI에. 프로필의 `ciPaths`(워크플로 paths와 같게: 바뀐 파일이 모두 밖이면 CI 없이 빠른 검사로 합친다) · `ciWaitMin`(검사가 긴 앱) · `selfHosted`(시작하지 않으면 러너가 꺼졌다고 알림) · `maxChats`(러너가 하나인 앱의 동시 대화 수)로 그 앱의 CI에 맞춘다.

## 이 앱에만 있는 것

- 중앙 대화가 하위 앱 고치기를 열기 · 급한 앱 고치기 · 작업 현황(`agentCentral.ts`), 중앙 방(`agentRoom.ts`)
- 기기 서버에서 대화 돌리기(`routes/chatPlace.ts`, 11/20): 한 컴퓨터만 대화를 돌리면 이 앱의 여러 맥 문제가 없다. 피드백 맡기기 · 자동 처리 설정도 서버 한 곳에서(`serverRelay.ts` · `routes/settings.ts`): 다른 맥은 맡기기를 서버로 넘기고 설정을 서버에 읽고 쓴다
- 소개 1대1 검사와 소개 PR 번호 조각(`aboutFragment`), 구조 래칫 — 그 앱에 같은 규칙이 있을 때만
- Codex 검토(`agentReview`), 시안 그림 보이기(`agentMockups`)
- 컴퓨터 크기에 맞춘 동시 대화 수(`appMemory.ts`): 대화를 한두 개만 돌리는 앱은 고정 수로 충분하다

## 점검

- [ ] 앱 고치기 대화가 실사용 앱 폴더의 파일을 바꾸지 못한다 (worktree 밖 쓰기가 막힌다)
- [ ] 에이전트가 `git push` · `gh pr merge`를 돌리면 막히고 도구를 쓰라는 말을 받는다
- [ ] 빠른 검사에서 떨어지면 아무것도 올라가지 않고, 고친 파일은 남는다
- [ ] CI가 빨갛거나 덜 끝났거나 main과 부딪히면 합치기가 까닭과 함께 거절된다
- [ ] 같은 피드백 항목을 두 곳에서 동시에 맡지 않는다 (맡음 표시를 먼저 올린다)
- [ ] 합친 뒤 앱이 새 버전으로 다시 켜지고, 돌던 대화가 이어진다
- [ ] 합쳤거나 보관한 대화의 작업 폴더와 브랜치가 얼마 뒤 사라지고, 그 대화의 시안은 대화 화면에 그대로 보인다
- [ ] 열려 있는 대화, 고치던 파일 · 올리지 않은 커밋 · 열린 PR이 있는 작업 폴더는 사라지지 않는다
- [ ] 치운 대화에 이어서 지시하면 작업 폴더가 새로 생기고 시안이 돌아와 있다

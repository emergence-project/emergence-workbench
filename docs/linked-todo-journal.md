# 기록과 일지의 할 일 연결

기록 파일이 연결된 할 일의 정본이다. 앱에서 만든 할 일은 기록의 `journal` 날짜·시각과 일지의 숨은 `<!-- rw-todo: target/id -->`로 연결한다. 일지에서 글·완료 표시를 고치거나 삭제해도 정본 기록의 같은 수정·삭제 경로를 사용한다. 바깥에서 일지를 고칠 때 이 숨은 줄을 보존하면 앞 항목을 끼우거나 지워도 연결이 유지된다. 기존 파일을 일괄 변환하지 않는다.

일지 API의 읽기 결과에 `link`가 있으면 체크·글 수정·삭제 요청에도 **읽었던 그 값**을 전달한다. PATCH 본문에는 `was`(읽었던 글)와 `link`, DELETE query에는 `was`와 `link`를 넣는다. 새 연결된 할 일에서 누락되거나 다른 값이면 409로 멈춘다. 날짜·번호·본문만으로 같은 글의 여러 항목을 구별하지 않는다. 연결 없는 수동 일지는 `link` 없이 사용할 수 있다.

명시된 연결이 있으면 같은 글의 수동 일지보다 우선한다. 숨은 연결이 없는 예전 기록은 날짜·시각·대상·글이 유일하게 일치할 때만 잇는다. 모호하거나 바깥에서 연결 글이 달라진 경우 글 수정·삭제는 어느 쪽도 쓰기 전에 409로 멈춘다. 기록 상태만 바꾸는 예전 동작은 유지하되 다른 일지 항목을 대신 고치지 않는다. 상대 파일이나 항목이 바깥에서 완전히 삭제됐으면 남은 항목만 수정·삭제하고 상대를 다시 만들지 않는다. 상대가 존재하지만 글·종류·연결이 달라졌거나 연결 후보가 모호하면 409로 멈춘다. 화면의 연결된 할 일 편집기는 위치 번호 대신 고유한 연결 식별자를 따라가므로 앞 항목을 지워도 다른 할 일을 고치지 않는다.

연결된 수정·삭제는 먼저 답·해시·모든 원문을 검사하고 임시 파일을 준비한 뒤 쓴다. 저장 실패는 이미 쓴 부분을 되돌린다. 되돌림 전에 바깥에서 내용·경로가 바뀌면 그 글을 보존하고 부분 저장을 알린다. 프로세스 종료까지 보장하는 다중 파일 트랜잭션은 아니므로, 부분 저장 안내가 나오면 기록과 일지를 다시 열어 확인한다.
